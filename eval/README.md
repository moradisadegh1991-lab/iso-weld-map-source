# زیرساخت ارزیابی موتور جوش (EPIC-7)

> «هیچ تغییر مدل، prompt یا موتوری بدون اجرای eval و **عدم افت** متریک‌ها به production نمی‌رود.»
> — `docs/epc-llm/02-reference-architecture.md` §۷٫۳

## چرا این اولین کار فنی پروژه است

موتور `lib/engine.js` تصمیم می‌گیرد **کجا جوش بخورد و اسپول کجا بریده شود**.
یک رگرسیون بی‌صدا در آن، یک خطای ساخت در کارگاه است. بدون معیار پایه (baseline)،
در ماه سوم نمی‌توان ثابت کرد چیزی بهتر شده — فقط می‌توان ادعا کرد.

این هارنس **هیچ وابستگی، کلید API، GPU یا شبکه‌ای لازم ندارد**. موتور قطعی است،
پس دقت آن روی هر کامیت، رایگان، قابل اندازه‌گیری است.

## اجرا

```bash
npm run eval           # اجرای کامل + گزارش
npm run eval:check     # همان، ولی با exit code غیرصفر در صورت رگرسیون  (CI)
npm run eval:update    # ثبت مجدد baseline — فقط وقتی تغییر عمدی و تأییدشده است

# اجرای یک مورد
node --import ./eval/register.mjs eval/run.mjs --only SW-265022A

# خروجی ماشین‌خوان برای داشبورد روند
node --import ./eval/register.mjs eval/run.mjs --json eval/results/run.json
```

## ساختار

```
eval/
  run.mjs               اجراکننده
  register.mjs          ثبت loader — نقطهٔ ورود node --import
  resolve-hook.mjs      اجازه می‌دهد lib/*.js بدون bundler در Node اجرا شود
  lib/metrics.mjs       محاسبهٔ امتیاز هر مورد و جمع‌بندی
  lib/report.mjs        رندر کنسول + مقایسه با baseline
  baseline.json         مرجع ثبت‌شده — هر اجرا با این سنجیده می‌شود (tracked)
  cases/golden/         نقشه‌های واقعی با رجیستر تأییدشده توسط مهندس
  cases/rules/          قواعد مستند موتور، به‌صورت موردی و ایزوله
  results/              خروجی اجرا — artefact، نه source
```

## دو نوع مورد آزمون

**`cases/golden/`** — نقشهٔ واقعی. `expect` **آن چیزی است که مهندس پایپینگ
تأیید کرده**، نه آنچه موتور چاپ می‌کند. این‌ها دیتاست طلایی هستند و هدف فاز ۰
رساندن آن‌ها به **۵۰ نقشه** است. امروز ۱ مورد دارد (`SW-265022A`).

> افزودن مورد جدید: از `cases/golden/_TEMPLATE.json` کپی بگیرید. کلید
> `_howToFill` راهنمای پر کردن است. **هر کلیدی در `expect` که شخصاً تأیید
> نکرده‌اید را حذف کنید** — انتظار تأییدنشده بدتر از نبودِ انتظار است.

**`cases/rules/`** — قواعد مستند در README (Tie-in = ۱ جوش Field، زانو با
pup = ۴ جوش، سه‌راهی = ۶، حد طول حمل، دروازهٔ MTO و…) هرکدام در یک هندسهٔ
حداقلی و ایزوله. این‌ها دیتاست طلایی **نیستند** — داده میدانی ندارند؛
مشخصات رفتاری موتورند.

## دیتاست دولایه

`input` در هر مورد طلایی، هم‌زمان دو چیز است:

1. **ورودی موتور** — برای سنجش لایهٔ تصمیم (همین هارنس، امروز)
2. **حقیقت مرجع استخراج** — برای سنجش لایهٔ بینایی وقتی نقشهٔ همان مورد به
   مدل داده شود و خروجی JSON آن با این `input` فیلدبه‌فیلد مقایسه گردد

یعنی هر نقشه‌ای که به `cases/golden/` اضافه می‌کنید، **هر دو لایه** را
امتیاز می‌دهد. ارزیابی لایهٔ استخراج به endpoint مدل نیاز دارد و بخش بعدی
EPIC-7 است؛ ساختار داده‌اش همین حالا آماده است.

## متریک‌ها

| متریک | معنا | چرا مهم است |
|---|---|---|
| `weldCount` | تطابق دقیق تعداد کل جوش | سخت‌گیرانه‌ترین متریک MVP — یک جوش کم یعنی یک ITR گمشده |
| `fieldWelds` | تطابق **مجموعهٔ** شماره جوش‌های Field | ایمنی‌محورترین: کدام جوش در سایت بسته می‌شود |
| `spoolCount` | تعداد اسپول | مبنای حمل و بارگیری |
| `register` | مقایسهٔ سطربه‌سطر (`loc`, `kind`, `nps`, `spool`, `role`) | دقیق‌ترین چک موجود |
| `registerFieldAccuracy` | دقت فیلدی micro-average روی همهٔ موارد | روند کیفیت در طول زمان |
| `warnings` | تعداد WARN موتور | افزایش ناگهانی = استخراج یا قاعده مشکوک |

## وضعیت هر مورد

| وضعیت | معنا |
|---|---|
| `PASS` | همهٔ انتظارها برقرار |
| `FAIL` | رگرسیون یا باگ — CI قرمز می‌شود |
| `XFAIL` | **شکاف شناخته‌شده**: قاعدهٔ مستند با رفتار موتور نمی‌خواند، علتش ثبت شده. CI را قرمز نمی‌کند |
| `XPASS` | یک شکاف شناخته‌شده حالا پاس می‌شود — یعنی کسی موتور را درست کرده؛ `expectedToFail` را از مورد بردارید |

شکاف‌های فعلی در `docs/epc-llm/04-engine-findings.md` ثبت شده‌اند.

## منطق دروازه

دروازه عمداً **نامتقارن** است:

- هر چیزی که موتور را **بدتر** کند، مسدود می‌شود
- هر چیزی که **بهتر** کند، بی‌صدا عبور می‌کند — بهبود نباید اجازه بگیرد
- موارد **جدید** گزارش می‌شوند ولی مسدود نمی‌کنند (baseline ندارند)
- مورد **ناپدیدشده** مسدود می‌کند — حذف یک تست، راه فرار از دروازه نیست

## به‌روزرسانی baseline

`npm run eval:update` فقط وقتی مجاز است که تغییر رفتار موتور **عمدی و
بازبینی‌شده** باشد. `baseline.json` را در همان PR کامیت کنید تا دلیل تغییر
در تاریخچه بماند.

> اگر موتور با رجیستر تأییدشدهٔ یک نقشهٔ طلایی مخالف بود، **`expect` را برای
> سبز شدن دست نزنید.** این یک finding است: ثبتش کنید. تنظیم انتظار برای
> رضایت کد، دقیقاً همان چیزی است که این هارنس برای جلوگیری از آن ساخته شده.
