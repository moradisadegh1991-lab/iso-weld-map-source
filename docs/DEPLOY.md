# استقرار روی Vercel

این سامانه برای اجرا روی یک نشانی اینترنتی ساخته شده است. گوشی فقط برای تست
است، نه هدف طراحی.

## آنچه Vercel لازم دارد

### ۱. پایگاه داده

PGlite که برای توسعه استفاده می‌شود روی دیسک محلی می‌نویسد، و فضای فایل
Vercel **موقت و غیرمشترک** است: هر نمونهٔ سرورلس دیسک خودش را دارد و بین
درخواست‌ها پاک می‌شود. پس روی Vercel حتماً یک Postgres واقعی لازم است.

```
DATABASE_URL=postgres://user:pass@host:5432/dbname?sslmode=require
```

هر Postgres مدیریت‌شده‌ای کار می‌کند (Neon، Supabase، یا یک سرور داخل شرکت با
دسترسی از بیرون). بعد از تنظیم:

```
npm run db:migrate
npm run auth:admin -- you@example.com 'یک عبارت عبور خوب' 'نام شما'
```

### ۲. راز امضای نشست

```
SESSION_SECRET=<دست‌کم ۳۲ نویسهٔ تصادفی>
```

بدون این، سرویس در حالت production **بالا نمی‌آید** — عمداً. یک مقدار
پیش‌فرض ثابت یعنی همهٔ استقرارها یک راز مشترک دارند که در یک مخزن عمومی است،
و هر کسی می‌تواند برای هر کاربری نشست بسازد.

تولیدش:

```
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

چرخاندن این مقدار، همهٔ نشست‌های باز را یک‌باره باطل می‌کند.

### ۳. کلید مدل

```
ANTHROPIC_API_KEY=...
```

روی سرور می‌ماند و هرگز به مرورگر نمی‌رود.

## دربارهٔ «رله»

اگر منظور این است که پروژه روی گوشی اجرا شود و Vercel فقط دسترسی اینترنتی
بدهد، آن یک **تونل** است نه استقرار (مثل Cloudflare Tunnel)، و Vercel این کار
را نمی‌کند: Vercel کد شما را اجرا می‌کند، ترافیک را به دستگاه دیگری پاس
نمی‌دهد.

دو گزینهٔ واقعی:

| روش | یعنی | وقتی مناسب است |
|---|---|---|
| استقرار روی Vercel | کد روی Vercel اجرا می‌شود، داده در Postgres مدیریت‌شده | استفادهٔ واقعی چند کاربره |
| تونل به گوشی | کد روی گوشی، یک URL عمومی به آن | فقط نمایش موقت؛ با خاموش شدن گوشی قطع می‌شود |

برای یک سامانهٔ EPC که چند نفر همزمان به آن وارد می‌شوند، گزینهٔ اول درست است.

## محدودیت‌هایی که باید بدانید

- **مدت اجرا:** استخراج تا ۳۰۰ ثانیه تنظیم شده (`maxDuration`). طرح Hobby آن
  را روی ۶۰ ثانیه می‌بندد؛ برای پاس‌های استخراج طرح Pro لازم است.
- **حجم درخواست:** سقف ۴.۵ مگابایت. تصاویر در مرورگر کوچک می‌شوند تا زیر آن
  بمانند.
- **نشست:** هشت ساعت، و چون در کوکی امضاشده است قبل از انقضا باطل نمی‌شود
  مگر با چرخاندن `SESSION_SECRET`.

## مسیر بعدی احراز هویت

درز Keycloak در `lib/authz.mjs` باز است: `createIdentityResolver` یک verifier
می‌گیرد و هیچ چیزِ پایین‌دستِ آن نمی‌داند چه چیزی هویت را تأیید کرده. مهاجرت
یعنی صدور توکن از Keycloak به‌جای جدول `user_credential` — هر قاعدهٔ دسترسی،
هر بررسی عضویت و هر سیاست RLS دست‌نخورده می‌ماند.
