## ۲. Epicها

### EPIC-1 · پایداری داده و چندکاربری — 🟢 لایهٔ داده پیاده شد
**چرا اول:** بدون این، هیچ‌کدام از قابلیت‌های دیگر معنا ندارند.

| Story | شرح | وضعیت |
|---|---|---|
| 1.1 | PostgreSQL + اسکیمای هسته | ✅ `db/migrations/001_core.sql` · runner با گارد checksum · `npm run db:migrate` |
| 1.2 | ذخیرهٔ فایل خام با hash | ✅ ذخیره‌سازی محتوا‌محور (SHA-256) · درایور local تست‌شده · درایور S3/MinIO نوشته، به bucket وصل نشده |
| 1.3 | پایدارسازی `extraction_run` | ✅ payload، `validation_checks` دست‌نخورده، توکن‌ها، مدل، زنجیرهٔ ممیزی تا بایت سند |
| 1.4 | احراز هویت + نقش‌ها | 🟡 **مجوزدهی** کامل و تست‌شده (`lib/authz.mjs`) · **احراز هویت** یک seam است؛ verifier واقعی به سرور Keycloak نیاز دارد |
| 1.5 | پروژه و واحد | ✅ با **Row Level Security** در خود پایگاه داده، نه `WHERE` در اپلیکیشن · نقش `app_rw` تا superuser آن را دور نزند |

**سیم‌کشی شد.** چهار route (`/api/projects`، `/api/documents`، `/api/runs`،
`/api/runs/[id]/approve`) و کامپوننت `SaveBar` — نقشه، رجیستر و تأیید حالا
پایدار می‌مانند.

**۴۲ تست روی PostgreSQL واقعی** (PGlite in-process): ۲۱ تست لایهٔ داده و ۲۱ تست
که **خود route handler ها** را مستقیم صدا می‌زنند — یعنی احراز هویت، بررسی
مجوز، RLS و پایداری در یک مسیر واقعی پوشش داده می‌شوند، بدون سرور و بدون مرورگر.

**نکتهٔ امنیتی:** رجیستر روی سرور از روی payload **دوباره محاسبه** می‌شود، نه
اینکه از کلاینت پذیرفته شود. مرورگر جای تصمیم‌گیری دربارهٔ محل جوش نیست.
همچنین hash ادعاشده توسط آپلودکننده نادیده گرفته می‌شود وقتی خود بایت‌ها موجودند.

جزئیات در [`db/README.md`](../../db/README.md).
