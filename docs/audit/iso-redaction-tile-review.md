# Review the exact redacted tiles locally

The redaction preview now displays the full-view JPEG and each overlapping JPEG tile produced by the existing image preparation pipeline. The image bytes, labels and order are copied into an immutable local snapshot; SHA-256 over a canonical UTF-8 JSON array identifies this exact local snapshot. When masks, source, or the project view change, the prior preview is invalidated. A delayed digest from an older selection cannot replace the current preview. On an insecure HTTP origin where Web Crypto is unavailable, the local images remain visible but there is no fingerprint and the UI requests HTTPS. If the size limit causes the existing tiling ladder to drop tiles, a warning says the output does not cover the whole drawing.

This is a review aid, not an authorization, a server-side signature, or proof that the image has no confidential content. A checksum says nothing about whether names outside masks remain visible. It is calculated in the browser and can be forged by a client. No model request is made, no external guard is relaxed, and text in the repair payload is not sanitized. Before any cloud send, the server must independently bind the reviewed/approved exact bytes and safe text to the user's project/session, reject stale or changed inputs, and the owner must settle the privacy workflow. No new migration.

Tests exercise invalid/missing crypto, image changes, relabeling and reordering. The browser driver uses a golden sample PDF, reconstructs the hash independently from the displayed JPEG data, checks the masked pixel, deliberately delays hashing while clearing masks, and asserts that a stale result does not reappear and no model endpoint is called. The checksum test does not prove the user's masks are complete or that a future server will enforce the binding.
