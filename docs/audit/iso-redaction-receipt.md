# Isometric preview integrity receipt

This change adds a short-lived server-signed receipt for an ordered bundle of redacted preview images. The server recomputes the same SHA-256 digest as the browser, binds it to the authenticated user, project and session credential, and expires it after five minutes. Verification recomputes the digest and checks those bindings. The receipt is held in browser memory; it is not saved as a review record. Signing uses a key derived from the configured `SECRETS_KEY` or `SESSION_SECRET`; instances must share that secret, and rotation invalidates outstanding receipts.

This is an integrity check only. It does not establish that a person inspected the images, that the labels reflect their actual spatial coverage, or that every project or client identifier was removed. Any authorized caller can request a receipt without interacting with the review controls. JPEG validation checks the format markers and canonical base64, not the validity or contents of the image. The receipt can be replayed until expiry; it is not bound to a source document or revision, and it does not cover OCR text or any other payload.

The endpoints make no model calls and do not authorize cloud transmission. The existing external extraction block remains in force. Before any future cloud integration, the design must address trustworthy server-side redaction of the source, bind the reviewed data to the exact outgoing image and text payload, enforce an appropriate authorization and replay policy, and resolve the project owner's privacy choices. A receipt alone must never be treated as proof of confidentiality or permission to send.
