## گام ۱ · پایگاه داده

سه مسیر، به ترتیب واقع‌بینی:

| مسیر | چه وقت | چطور |
|---|---|---|
| **PGlite** | همین حالا، روی لپ‌تاپ، بدون هیچ نصبی | کاری نکنید — پیش‌فرض است |
| **Postgres در Docker** | تیم دو نفره، تست روی داده واقعی | `docker run -e POSTGRES_PASSWORD=… -p 5432:5432 postgres:16` |
| **Postgres سازمانی** | تولید | DBA یک دیتابیس و یک کاربر می‌دهد |

```bash
export DATABASE_URL=postgres://isoweld:PASSWORD@host:5432/isoweld
```

**کاربری که اپلیکیشن با آن وصل می‌شود نباید superuser باشد.** PostgreSQL به
superuser اجازهٔ عبور از Row Level Security می‌دهد، و آن‌وقت جداسازی پروژه‌ها
تزئینی است. migration نقش `app_rw` را می‌سازد و کد خودش به آن سقوط می‌کند؛
کاربر اتصال فقط باید حق `SET ROLE app_rw` داشته باشد.

## گام ۳ · احراز هویت

```bash
AUTH_MODE=dev            # لپ‌تاپ: توکن همان نام کاربر است
```

برای تولید این کافی نیست و ماژول بدون verifier **throw می‌کند**، نه اینکه به

### کاربران، نقش‌ها و حوزه‌های کاری

- **توسعه‌دهنده** (دسترسی به همهٔ پروژه‌ها و همهٔ اختیارات) فقط از خط فرمان ساخته می‌شود:

  ```bash
  npm run auth:developer -- someone@example.com "نام"
  # حساب ساخته می‌شود (اگر نباشد) و یک لینک یک‌بارمصرف /setup?token=… چاپ می‌شود؛
  # با APP_URL=https://… لینک کامل چاپ می‌شود. رمز را خود صاحب حساب تعیین می‌کند.
  ```

  با PGlite (دیتابیس درون‌فرایندی) این فرمان را **وقتی سرور خاموش است** اجرا کنید: فقط یک
  فرایند می‌تواند آن را در دست داشته باشد. با PostgreSQL محدودیتی نیست.
- **مدیر پروژه** در صفحهٔ «کاربران و دسترسی» (`/admin`) کاربر دعوت می‌کند و برای هر نفر این
  موارد را تعیین می‌کند:
  - **نقش:** چه کاری می‌تواند بکند.
  - **حوزه‌های کاری:** منوی او، و اینکه در کدام رشته‌ها می‌تواند ثبت کند.
  - **طرف بازرسی:** از طرف چه کسی امضا می‌کند.

  دعوت یک لینک یک‌بارمصرف (۷۲ ساعت) می‌دهد. رمز هرگز از دست مدیر نمی‌گذرد.
- **حوزهٔ کاری:** اگر هیچ حوزه‌ای علامت نخورده باشد، یعنی همه. مدیر پروژه و توسعه‌دهنده همیشه در همهٔ حوزه‌ها هستند.
  - محدودیت روی **ثبت** است و در سرور، یک‌جا برای همهٔ مسیرها، اعمال می‌شود. همگام‌سازی سایت هم برای هر عملیات جدا بررسی می‌کند.
  - **خواندن** باز است، چون شناسنامهٔ یک تگ همهٔ رشته‌ها را دارد.
- کارهایی که از یک پروژه فراتر می‌روند با توسعه‌دهنده است، نه مدیر پروژه:
  - بازنشانی رمزِ حسابی که رمز دارد (ممکن است عضو پروژه‌های دیگر هم باشد)؛
  - غیرفعال کردن حساب (نشست‌هایش هم باطل می‌شود)؛
  - دادن نقش توسعه‌دهنده.

## گام ۴ · ارائه‌دهندهٔ مدل

**کلید کجا می‌رود:** فایل `.env.local` در ریشهٔ مخزن. این فایل gitignore شده
است، پس کلید هرگز به GitHub نمی‌رسد. از روی `.env.example` بسازیدش:

```bash
cp .env.example .env.local     # یک بار
# بعد خط ANTHROPIC_API_KEY را در .env.local از کامنت دربیاورید
npm run dev                    # Next خودش .env.local را می‌خواند
npm run doctor                 # باید گام ۴ را ✓ نشان دهد
```

کلید **فقط سمت سرور** خوانده می‌شود. هرگز در بدنهٔ درخواست نفرستیدش: کلیدی که
در مرورگر باشد، در devtools و در لاگ هر پروکسی میان راه هم هست.

روی سرور واقعی (Vercel / systemd / Docker) به‌جای فایل، همان نام را در
Environment Variables ِ همان سرویس بگذارید.

```bash
# امروز
LLM_PROVIDER=anthropic
ANTHROPIC_API_KEY=sk-ant-…

# وقتی خوشه بالا آمد — و این تنها تغییر است
LLM_PROVIDER=openai-compatible
LLM_BASE_URL=http://vllm:8000/v1
LLM_MODEL=Qwen/Qwen2.5-VL-32B-Instruct
```

بدون این، همه‌چیز جز استخراج کار می‌کند: دکمهٔ «نمونه بدون سرور» کل موتور،
مدل سه‌بعدی و رجیستر را بدون هیچ فراخوانی مدل نشان می‌دهد.

## گام ۵ · ذخیره‌سازی

نقشه‌ها، اسناد و عکس‌های Punch با هش SHA-256 محتوایشان نگه داشته می‌شوند. دو حالت:

- **`STORAGE_DRIVER=local`** (پیش‌فرض): پوشهٔ `STORAGE_ROOT` (پیش‌فرض `.storage`) روی همین
  سرور. برای یک سرور کافی است.
- **`STORAGE_DRIVER=s3`**: یک bucket در MinIO. برای **بیش از یک سرور برنامه** لازم است (وگرنه
  فایل روی یک سرور می‌نشیند و سرور دیگر آن را ندارد). **بارگذاری مستقیم نقشه‌های بزرگ‌تر از
  ۳٫۴ مگابایت** هم فقط با MinIO کار می‌کند. بدون MinIO، چنین نقشه‌ای فقط با هش ثبت می‌شود
  (`pending://`).

### راه‌اندازی MinIO

۱. **bucket و کاربر برنامه**، با حساب ادمین MinIO (`mc`). کاربر برنامه فقط می‌خواند و
می‌نویسد، **حذف نمی‌کند**. فایل‌ها مدرک‌اند:

```bash
mc alias set epc http://minio:9000 <admin> <admin-secret>
mc mb epc/epc-files
mc admin policy create epc epc-app deploy/minio/epc-app-policy.json   # نام bucket را اگر فرق دارد اصلاح کنید
mc admin user add epc epc-app '<یک رمز طولانی>'
mc admin policy attach epc epc-app --user epc-app
mc version enable epc/epc-files      # توصیه: یک بازنویسی ادمینی هم نسخهٔ قبلی را از بین نمی‌برد
```

۲. **متغیرها** (در `.env.local` یا سرویس):

```bash
STORAGE_DRIVER=s3
S3_ENDPOINT=http://minio:9000            # آدرسی که سرور برنامه می‌بیند
S3_PUBLIC_ENDPOINT=https://files.example.ir   # آدرسی که مرورگر کاربران می‌بیند (برای بارگذاری مستقیم)
S3_BUCKET=epc-files
S3_ACCESS_KEY_ID=epc-app
S3_SECRET_ACCESS_KEY=…
```

۳. **آزمون و انتقال**:

```bash
npm run storage -- setup      # bucket هست؟ نوشتن → خواندن → مقایسه
npm run storage -- migrate    # فایل‌های .storage به bucket، هرکدام با هش کنترل‌شده؛ تکرارش فقط تازه‌ها را می‌برد
npm run storage -- verify     # همهٔ فایل‌هایی که پایگاه داده نام می‌برد: هست؟ هش درست است؟
npm run doctor                # گام ۵ باید bucket را «✓» نشان دهد
```

`migrate` چیزی را حذف نمی‌کند و URI های پایگاه داده را هم عوض نمی‌کند (آن جدول‌ها
append-only هستند). درایور S3 یک `local://…` قدیمی را همان کلید در bucket می‌خواند، چون کلید
هش فایل است، نه نام سرور.

**چه تضمین می‌شود:**
- MinIO بایت‌هایی را که با هش اعلام‌شده نخوانند نمی‌پذیرد. هش در امضای URL بارگذاری
  مستقیم هست، پس مرورگر فقط همان فایل را می‌تواند بفرستد.
- سرور فایلی را که دیگر با هش خودش نمی‌خواند برنمی‌گرداند؛ جایگزینی فایل پشت سر برنامه
  خطا می‌دهد، نه فایل دیگر.
- رمز اشتباه یا MinIO ازکارافتاده خطاست، نه «فایل نیست». برنامه هیچ‌وقت بی‌صدا به دیسک
  محلی برنمی‌گردد.

**CORS:** بارگذاری مستقیم از مرورگر به MinIO بین‌دامنه‌ای است. MinIO به‌طور پیش‌فرض CORS را
برای S3 API باز دارد؛ اگر `MINIO_API_CORS_ALLOW_ORIGIN` را محدود کرده‌اید، آدرس برنامه را در
آن بگذارید.

**پشتیبان‌گیری:** با MinIO از bucket پشتیبان بگیرید (`mc mirror`)، نه از `.storage`.

## گام ۹ · نقشه‌ها

UI: شناسه → پروژه → آپلود → استخراج → تب **بازبینی**.

ورودی **PDF یا تصویر** (PNG · JPG). یک PDF چندبرگی — همان چیزی که از دفتر
مهندسی می‌آید — باز می‌شود، بندانگشتی هر برگ رندر می‌شود، و شما برگ را از
روی شکل مسیر انتخاب می‌کنید؛ نیازی به تبدیل دستی به تصویر نیست.

نقشهٔ CAD **برداری** است: در ۳۰۰ DPI رندر می‌شود (A3 ⇒ ۴۹۵۸×۳۵۰۴ px) که از

اپراتور اسکنر به ارث رسیده. رندر و تقسیم به کاشی در مرورگر شما انجام می‌شود،
پس فایل اصلی جایی نمی‌رود.

> **هشدار نگهداری —** ماژول عمداً از build ِ `legacy` ِ pdf.js استفاده می‌کند.
> build ِ پیش‌فرضِ نسخهٔ ۶ متدی را صدا می‌زند که هیچ مرورگری ندارد، و خرابی‌اش
> *جزئی* است: تعداد صفحه‌ها و اندازهٔ برگ‌ها درست برمی‌گردد و فقط رندر خالی
> می‌ماند. بعد از هر ارتقای `pdfjs-dist` اجرا کنید `npm run pdfjs:worker` و

## گام ۱۱.۵ · رجیستر پیمانکار — جایی که دقت عدد می‌شود

تب **حقیقت مرجع** در پنل راست. رجیستر جوش پیمانکار را یا از Excel کپی و
Paste کنید، یا فایل CSV/XLSX بدهید.

سرستون‌ها به هر دو زبان شناخته می‌شوند (`Weld No` · `WELD_NO` · `شماره جوش`،
`SHOP/FIELD` · `محل جوش`، `JOINT` · `نوع جوش`، `NPS` · `قطر`).

```
Weld No   SHOP/FIELD   JOINT     NPS
W-01      FIELD        TIE IN    28
W-02      Shop         Butt Weld 28
```

خروجی سه چیز است:

| | معنا |
|---|---|
| **تعداد جوش** | جوشی که پیدا نشده، و جوشی که اضافه ساخته شده — **جدا** |
| **دقت هر فیلد** | فقط روی جوش‌هایی که در هر دو طرف هستند |
| **جدول اختلاف‌ها** | کدام جوش، کدام فیلد، پیمانکار چه گفت و محاسبه چه گفت |

سه تصمیم که عمدی‌اند و عدد را از تورم نگه می‌دارند:

۱. **ستونی که شناخته نشود حدس زده نمی‌شود.** آن فیلد سنجیده نمی‌شود — نه غلط
   حساب می‌شود نه درست. حدسِ غلط، دقیقاً همان عددی را خراب می‌کند که این
   بخش برای تولیدش ساخته شده.
۲. **جوش گم‌شده و جوش اضافه با هم میانگین نمی‌گیرند.** دو خرابی متفاوت‌اند:
   یکی هرگز بازرسی نمی‌شود، دیگری در کارگاه سؤال می‌سازد.
۳. **فیلدی که رجیستر ندارد، سنجیده نمی‌شود** — نه صفر، نه صد.

دکمهٔ **دانلود مورد آزمون golden** فایل `eval/cases/golden/` را می‌سازد و
`expect` را **از رجیستر پیمانکار** می‌نویسد، نه از خروجی موتور. جهتش کل
ماجراست: انتظاری که از خروجی خودمان ساخته شود، هر اجرای بعدی را با باگ‌های
امروز موافق می‌کند. `verifiedBy` را خودتان پر کنید.
