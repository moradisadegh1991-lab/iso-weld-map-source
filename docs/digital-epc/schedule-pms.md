# برنامهٔ زمان‌بندی (MS Project) و PMS

صفحه: **مدیریت پروژه ◄ کنترل پروژه ◄ برنامه و PMS** (`/pms`).

## از کجا می‌آید

| فایل | چطور خوانده می‌شود |
|---|---|
| برنامهٔ MS Project | به‌صورت **XML (MSPDI)**: در MS Project ◄ File ◄ Save As ◄ XML Format. فایل ‎.mpp بدون Java خوانده نمی‌شود؛ XML همان برنامه است، فعالیت به فعالیت. |
| PMS (اکسل) | برگهٔ `PMS` (یا اولین برگه) با چیدمان فعلی: سطح در ستون‌های B تا G، کد گام H، شرح I، واحد J، وزن گام K، W.F در L، مقدار M، مقدار انجام‌شده X، پیشرفت قبلی/این دوره/کل در Y/Z/AA. |

هر ورود یک **رکورد** است و ویرایش نمی‌شود (پایگاه داده UPDATE/DELETE را رد می‌کند). فایل تازه یعنی ورود تازه، و تازه‌ترین ورود «جاری» است. دو چیز بعد از ورود **کنار** آن اضافه می‌شود، نه داخلش:

- **پیوند** آیتم PMS به فعالیت خلاصهٔ برنامه (`pms_link`) — تازه‌ترین پیوند هر آیتم معتبر است؛ با UID فعالیت ذخیره می‌شود، پس با ورود نسخهٔ تازهٔ برنامه از بین نمی‌رود.
- **پیشرفت گام** بعد از فایل (`pms_progress`) — با تاریخ و منبع (مثلاً شمارهٔ گزارش روزانه)؛ برای هر تاریخ، تازه‌ترین گزارشِ تا آن روز حساب می‌شود.

تنها چیزی که به خود ورود PMS اضافه می‌شود **تاریخ داده** است، و فقط یک بار، وقتی فایل آن را ننوشته باشد.

## موتور چه می‌کند

- **برنامه:** نام، WBS/outline، شروع و پایان جاری، **خط مبنا**، شروع و پایان واقعی، مدت (روز کاری با MinutesPerDay خود فایل)، درصد انجام، پیوندها (FS/SS/FF/SF و تأخیر)، و فیلدهای سفارشی برنامه‌ریز با نام مستعار خودشان (WF، Plan%، Project Price …). چیزی دوباره زمان‌بندی نمی‌شود.
- **PMS:** پیشرفت هر گروه را از گام‌ها با وزن W.F دوباره حساب می‌کند و با آنچه فایل نوشته مقایسه می‌کند. ناسازگاری‌ها **اصلاح نمی‌شوند، نشان داده می‌شوند**: جمع وزن زیرمجموعه ≠ وزن گروه، جمع وزن گام‌های آیتم ≠ ۱۰۰٪، W.F گام ≠ وزن آیتم × وزن گام، پیشرفت بیرون از ۰–۱۰۰٪، «کل» ≠ «قبلی + این دوره»، پیشرفت نوشته‌شدهٔ گروه ≠ جمع وزنی گام‌ها.
- **پیوند خودکار** فقط وقتی قطعی است: نام یکسان، یا **کد بخش** یکسان (`1A`، `2A1`، `5A+5C`) و فقط یک فعالیت آن را داشته باشد. نام‌های نزدیک با غلط املایی («Primery TLE (E-110 A)» / «Primary TLE (E-110A)») را شخص پیوند می‌دهد.
- **منحنی S:** وزن هر آیتم پیوندخورده به‌طور یکنواخت روی روزهای فعالیتش پخش می‌شود (یک منحنی با تاریخ‌های خط مبنا، یک منحنی با تاریخ‌های جاری) — **مقدار محاسبه‌شده**. منحنی فقط بخش پیوندخورده را می‌پوشاند و سهمش را می‌گوید. پیشرفت واقعی فقط وقتی روی منحنی می‌آید که تاریخ داشته باشد.

## کورهٔ F-110 (پروژهٔ `F10`)

```
npm run furnace:load -- you@example.com [--code F10] [--data-date YYYY-MM-DD]
# روی سرور:  epc run furnace:load you@example.com
```

| | |
|---|---|
| برنامه | `data/f10/F10.mpp` (اصل) و `F10.xml` (همان، به MSPDI با MPXJ) — ۳۷۵ فعالیت، ۳۸۶ پیوند، تاریخ وضعیت ۲۰۲۱-۱۰-۲۲، پایان جاری ۲۰۲۲-۰۷-۱۹ در برابر مبنای ۲۰۲۲-۰۲-۱۵ (۱۵۴ روز) |
| PMS | `data/f10/pms.xlsx` — OLF1 و OLF2، ۸۷۵ گام؛ جمع وزنی گام‌ها **۶۳٫۰۳۰۴٪** = عدد خود فایل؛ ۱۳ گام که «کل» با «قبلی + این دوره» نمی‌خواند |
| پیوند | ۴۲ از ۸۷ آیتم شاخهٔ OLF1 (۳۱ هم‌نام، ۱۱ هم‌کد) |
| فرض ثبت‌شده | برنامه مال کورهٔ OLF1 است (وضعیت: پیشنهادی، در رجیستر فرض‌ها) — برنامه فقط «F-110» دارد و نام واحد ندارد؛ OLF2 برنامه ندارد |
| اطلاعات ناقص | تاریخ دادهٔ PMS در فایل نیست (آخرین ذخیرهٔ فایل ۲۰۲۳-۰۴-۱۰ است، که تاریخ داده نیست) |

**ناسازگاری بین دو سند که موتور تصمیمش را نمی‌گیرد:** تگ تجهیزات در PMS و برنامه یکی نیست (مثلاً Secondary TLE: `E-1120` در PMS و `E-1110` در برنامه؛ Decoke Drum: `D-11110` و `D-110`). تا وقتی تگ درست با لیست تجهیزات تأیید نشده، این آیتم‌ها به شناسنامهٔ تجهیز (spine) وصل نمی‌شوند.
