# واژه‌نامهٔ پلتفرم EPC

هر اصطلاحی که در منوها، فرم‌ها، پیام‌ها، گزارش‌ها و راهنمای سناریو (`03-scenario-dm-pump.md`) می‌آید،
با معنایش **در همین پلتفرم**. جایی که عدد یا قاعده‌ای از یک استاندارد آمده، همان عددی است که موتورهای
پلتفرم با آن حکم می‌دهند و بند استاندارد کنارش نوشته شده است.

> **قاعدهٔ کلی پلتفرم:** «استخراج، تصمیم، امضا» از هم جدا هستند. مدل زبانی فقط داده می‌خواند (استخراج)؛
> حکم را موتور قطعی می‌دهد (تصمیم)؛ و آدمِ مسئول امضا می‌کند. جایی که داده یا معیاری نیست، پلتفرم
> «نامعلوم» می‌گوید و عددی از خودش نمی‌سازد.

## ۱. پلتفرم و ساختار پروژه

| اصطلاح | کامل / معادل | در این پلتفرم |
|---|---|---|
| **EPC** | Engineering, Procurement, Construction | قراردادی که طراحی، خرید و ساخت یک واحد را یک پیمانکار اصلی بر عهده دارد. پلتفرم کار همین پیمانکار را از مدرک طراح تا تحویل به بهره‌بردار دنبال می‌کند. |
| **پروژه** | Project | ظرف همهٔ داده‌ها؛ داده‌های هر پروژه در دیتابیس از پروژه‌های دیگر جداست (Row Level Security). کد کوتاه دارد، مثل `DMW`. |
| **مشخصات پروژه** | Project spec | همهٔ عددهایی که موتورها با آن حکم می‌دهند: ارز قرارداد، تراز گرید، عمل‌آوری بتن، ولتاژ LV، تلورانس کالیبراسیون، حدود تست گاز، مهلت‌ها، الگوی FLOC و… . تا ثبت نشوند، حکم مربوط «نامعلوم» است. |
| **واحد** | Unit | بخش فرایندی کارخانه (مثلاً واحد 70). تراز گرید می‌تواند برای هر واحد جدا باشد. |
| **سیستم / ساب‌سیستم** | System / Subsystem | تقسیم‌بندی تکمیل و راه‌اندازی. هر تگ، خط، کابل و ابزار زیر یک ساب‌سیستم است (مثلاً `70-01`)، و MC، RFC و RFSU برای هر ساب‌سیستم جدا امضا می‌شوند. |
| **تگ** | Tag | شناسهٔ یک قلم تجهیز یا سازه (مثلاً `P-7001`، `D-7002`، `FDN-P-7001`). «شناسنامهٔ تجهیز» همهٔ رشته‌های یک تگ را یک‌جا نشان می‌دهد. |
| **رشته** | Discipline | سیویل، سازه، مکانیک/تجهیزات، پایپینگ، برق، ابزار دقیق، رنگ و عایق. |
| **پیمانکار و پکیج** | Contractor / Contract package | شرکت‌های اجرایی (مثلاً `C-CIV`، `C-MEC`، `C-EI`) و محدودهٔ کارشان؛ روی رکوردها، پانچ‌ها و مجوزها نام برده می‌شوند. |
| **زنجیرهٔ تقدم** | Precedence chain | ترتیب مراحل هر نوع کار (مثلاً پمپ: فونداسیون ← استقرار ← گروت ← الایمنت ← اتصال پایپینگ ← …). مرحله‌ای که پیش‌نیازش انجام نشده «منتظر» است؛ اگر خارج از ترتیب ثبت شود، پرچم «خارج از ترتیب» می‌خورد. |
| **مرحلهٔ مشتق (⚙)** | Derived step | مرحله‌ای که از دادهٔ رشتهٔ دیگر خوانده می‌شود و دکمهٔ ثبت ندارد؛ مثلاً «فونداسیون و بولت» پمپ از سیویل، «جوشکاری کارگاهی» اسپول از رجیستر جوش، «تست فشار» از پکیج تست. |
| **آمادهٔ شروع / منتظر / انجام شد / ندارد** | — | وضعیت یک مرحله. «ندارد» یعنی به این آیتم اعمال نمی‌شود (مثلاً اسپولی که جوش کارگاهی ندارد) و پیشرفت حساب نمی‌شود. |
| **تاریخ انجام کار** | Work date | فیلد بالای صفحه‌هایی که «ثبت انجام» یک‌کلیکی دارند؛ هر ثبت با همین تاریخ ذخیره می‌شود، نه تاریخ امروز. تاریخ آینده رد می‌شود. |
| **روز پروژه** | Project day | تعداد روز از «تاریخ شروع» پروژه (روز 0). کنار «تاریخ انجام کار» می‌شود N را نوشت تا تاریخ پر شود، و زیر فیلدهای تاریخ فرم‌ها «روز N پروژه» نوشته می‌شود. روزِ هنوز نرسیده گفته می‌شود و ثبت نمی‌شود. |
| **فهرست جوش (ورود دستی / Excel)** | Weld list entry | رجیستر جوش برای نقشه‌ای بدون هندسه: شماره، اسپول، Shop/Field، نوع و قطر هر جوش، دستی یا از Excel/CSV (ستون‌ها از روی نام سرستون شناخته می‌شوند). «دادهٔ واردشده توسط کاربر» است؛ سامانه فقط بررسی می‌کند (شمارهٔ تکراری، محل نامعلوم، جوش کارگاهی بدون اسپول، قطر) و حدس نمی‌زند. تراز و زیرزمینی/روزمینی نامعلوم می‌ماند؛ بین رویژن‌ها جوش با شماره‌اش شناخته می‌شود. |
| **بدون فایل نقشه** | No file on record | سندی که رجیسترش تایپ شده ولی فایلش هنوز بارگذاری نشده. فایل که با همان شماره و رویژن برسد، به همان سند پیوست می‌شود. |
| **فرضیات و اطلاعات ناقص** | Assumption / UNKNOWN register | فهرست آنچه پروژه هنوز معلوم نکرده (مثلاً معیار IR ولتاژ متوسط). هر ردیف می‌گوید کدام حکم بدون آن ممکن نیست. |
| **میز کار** | Dashboard | نمای کلی پروژه برای کاربر وارد‌شده. |
| **سایت (آفلاین) / بستهٔ سایت** | Field pack | بارگیری اطلاعات یک ساب‌سیستم روی گوشی، ثبت بدون اینترنت و «همگام‌سازی» بعدی؛ هر عملیات شناسهٔ یکتا دارد و دوبار ثبت نمی‌شود. |
| **برچسب QR** | QR label | برچسب قابل چاپ برای تگ، اسپول، کابل و ابزار؛ اسکن آن در سایت همان آیتم را باز می‌کند. |
| **رجیستر (ایزومتریک)** | Weld register | فهرست جوش‌ها و اسپول‌های یک نقشه که موتور از هندسه و MTO می‌سازد. «تأیید رجیستر» با هش SHA-256 آنچه امضا شده ثبت می‌شود و پس از آن تغییر فقط با رویژن جدید ممکن است. |
| **گیت ارزیابی** | Eval gate | آزمون خودکار دقت استخراج در برابر نقشه‌های مرجع؛ هر تغییری که دقت را پایین بیاورد رد می‌شود (`npm run eval:check`). |
| **حقیقت مرجع** | Ground truth | رجیستر پیمانکار یا دادهٔ دستی تأییدشده که دقت استخراج با آن سنجیده می‌شود. |

## ۲. کاربران، نقش‌ها و امضا

| اصطلاح | در این پلتفرم |
|---|---|
| **نقش** | سطح اختیار هر نفر در یک پروژه: **viewer** (فقط دیدن)، **qc** (ثبت کار سایت، NDT، بازرسی، پانچ)، **engineer** (به‌علاوهٔ مهندسی: تأیید رجیستر، ITP، کلاس لوله، مدارک، خرید، امضای MC، تحویل)، **admin** (مدیر پروژه: همه، به‌علاوهٔ مدیریت کاربران)، **designer** (طراح: فقط «پرتال طراح»)، **developer** (توسعه‌دهنده: همهٔ پروژه‌ها؛ فقط از خط فرمان ساخته می‌شود). |
| **حوزهٔ کاری** | رشته‌هایی که یک نفر می‌تواند در آن‌ها **ثبت** کند (خواندن برای همه باز است). بدون انتخاب یعنی همه. |
| **طرف بازرسی** | از طرف چه کسی امضای بازرسی می‌کند: **پیمانکار**، **کارفرما** یا **TPI** (بازرس شخص ثالث). در «کاربران و دسترسی» تعیین می‌شود. |
| **اصل چهار چشم** | کسی که کاری را ثبت، تهیه یا امضا کرده، خودش آن را تأیید یا پذیرش نمی‌کند: تهیه‌کنندهٔ ITP تأییدش نمی‌کند، ثبت‌کنندهٔ تست فشار نمی‌پذیردش، امضاکنندهٔ MC از طرف کارفرما نمی‌پذیردش، کسی که پانچ را رفع کرده تأییدش نمی‌کند، درخواست‌دهندهٔ مجوز کار صادرش نمی‌کند. |
| **امضا / پذیرش** | امضا را پیمانکار (EPC) می‌زند که می‌گوید کار تمام است؛ پذیرش را کارفرما (یا طرف صاحب اختیار) می‌زند. امضاها همیشه با زمان همان لحظه ثبت می‌شوند. |
| **پرتال طراح** | تنها صفحه‌ای که حساب «طراح» باز می‌کند: ارسال ترانسمیتال با فایل‌ها، کامنت‌هایی که پروژه با ترانسمیتال پاسخ برگردانده و پاسخ طراح به هر کدام، و فهرست مدارک MDR. بررسی داخلی پروژه (توزیع بین رشته‌ها، کامنتی که هنوز پاسخ‌داده‌نشده، کدگذاری) در آن نیست؛ و بررسی‌کنندگان پروژه فرم‌های طراح را ندارند — کامنت را روی پاسخ خود طراح می‌بندند. |
| **دعوت** | لینک یک‌بارمصرف (۷۲ ساعت) برای عضو جدید؛ رمز را خود شخص تعیین می‌کند و از دست مدیر نمی‌گذرد. |

## ۳. کنترل مدارک

| اصطلاح | کامل / معادل | در این پلتفرم |
|---|---|---|
| **MDR** | Master Document Register | فهرست همهٔ مدارکی که پروژه باید داشته باشد؛ هر ردیف رشته، نوع، تگ تجهیز (برای دیتاشیت) و ساب‌سیستم دارد و اینکه آیا «تأیید کارفرما پیش از IFC» لازم است. |
| **رویژن** | Revision | نسخهٔ یک مدرک (A، B برای بررسی؛ 0، 1 برای ساخت). رویژن جدید قبلی را **منسوخ** (Superseded) می‌کند و گزارش‌ها فقط رویژن جاری را می‌شمرند. |
| **رویژن ساخت** | Construction revision | آخرین رویژنی که با هدف IFC یا AB صادر شده؛ کار سایت فقط بر اساس آن مجاز است. |
| **IFR / IFA / IFC / AB / VOID** | Issued for Review / Approval / Construction, As-Built, Void | هدف صدور یک رویژن: برای بررسی، برای تأیید، برای ساخت، چون‌ساخت، باطل. |
| **ترانسمیتال** | Transmittal | برگهٔ ارسال رسمی مدارک. **ورودی** از طراح به EPC (مثلاً `DES-TR-7001`؛ خود طراح از «پرتال طراح» می‌فرستد) و **پاسخ/خروجی** از EPC (مثلاً `EPC-RT-7001`). |
| **کدهای برگشت** | Return codes | **کد ۱** تأیید، **کد ۲** تأیید با کامنت، **کد ۳** رد (ارسال مجدد)، **کد ۴** برای اطلاع. کد ۱ به مدرکی که کامنت باز دارد داده نمی‌شود. |
| **IDC** | Inter-Discipline Check | توزیع یک مدرک بین رشته‌ها برای بررسی و کامنت، پیش از پاسخ به طراح. |
| **کامنت** | Comment | ایراد ثبت‌شده روی یک رویژن؛ تا بسته نشود، مدرک کد ۱ نمی‌گیرد. |
| **مهلت بررسی** | Review period | تعداد روزی که EPC برای پاسخ به ترانسمیتال دارد (از مشخصات پروژه). |
| **P&ID** | Piping & Instrumentation Diagram | نقشهٔ فرایندی لوله و ابزار دقیق. |
| **دیتاشیت** | Datasheet (DS) | مشخصات فنی یک تجهیز؛ رویژن IFC آن مبنای «شرایط طراحی» در شناسنامهٔ نگهداری است. |
| **ایزومتریک** | Isometric (ISO) | نقشهٔ سه‌بعدی تک‌خطی یک خط لوله، با BOM؛ منبع رجیستر جوش. |
| **GA** | General Arrangement | نقشهٔ جانمایی کلی تجهیز (از مدارک فروشنده). |

## ۴. خرید و پیگیری

| اصطلاح | کامل / معادل | در این پلتفرم |
|---|---|---|
| **MR** | Material Requisition | درخواست خرید فنی مهندسی، با رویژن؛ ردیف‌هایش می‌گویند چه چیزی، چند تا، با کدام مشخصات، و آیا **FAT لازم** است. |
| **مناقصه / استعلام** | Tender / RFQ | صدور MR برای فروشندگان و دریافت پیشنهاد. |
| **پیشنهاد** | Bid | قیمت و مشخصات هر فروشنده. |
| **ارزیابی فنی** | Technical evaluation | «فنی قابل‌قبول» یا «فنی مردود»؛ فقط پیشنهاد فنی قابل‌قبول قابل واگذاری است. |
| **واگذاری** | Award | انتخاب برنده و ساخت PO از همان پیشنهاد. واگذاری به پیشنهاد گران‌تر از کمترین قیمت قابل‌قبول بدون دلیل ثبت‌شده رد می‌شود. |
| **فروشندگان** | Vendor register | فهرست شرکت‌هایی که پروژه از آن‌ها می‌خرد: کد، نام، کالا/خدمات، شخص رابط، ایمیل، تلفن، نشانی، شهر و کشور، وب‌سایت؛ همان کد دوباره یعنی ویرایش. پیشنهاد و PO فروشنده را از همین فهرست برمی‌دارند. |
| **PO** | Purchase Order | سفارش خرید؛ ردیف‌هایش تاریخ قول‌داده، پیش‌بینی و نیاز سایت دارند. |
| **پیگیری** | Expediting | دنبال کردن تاریخ‌ها: **Slip** (عقب‌افتادن پیش‌بینی از قول)، **Float** (فاصلهٔ پیش‌بینی تا نیاز سایت). |
| **VDRL** | Vendor Document Requirement List | مدارکی که فروشنده باید بدهد (GA، منحنی عملکرد، IOM، …)، هر کدام با مهلت؛ بعضی «پیش از FAT» لازم‌اند. |
| **منحنی عملکرد** | Performance curve | دبی–هد پمپ از سازنده. |
| **FAT** | Factory Acceptance Test | بازرسی/آزمون در کارخانهٔ سازنده پیش از حمل. نتیجه: قبول، رد، یا **معاف (با دلیل)**. پیش از تأیید مدارک «پیش از FAT» ثبت نمی‌شود. |
| **IRN** | Inspection Release Note | برگهٔ آزادسازی برای حمل پس از FAT قبول یا معاف؛ بدون آن ردیف «آزاد برای حمل» نمی‌شود. |
| **محموله** | Shipment | ارسال و **ورود به سایت** (Site receipt)؛ وضعیت ردیف: سفارش‌شده ← منتظر FAT ← آزاد برای حمل ← حمل شد ← رسید سایت. |
| **Vendor Data Template** | — | مشخصات پلاک (سازنده، مدل، سریال، سال ساخت) که از فروشنده گرفته و به شناسنامهٔ نگهداری منتقل می‌شود. |

## ۵. انبار و مواد

| اصطلاح | کامل / معادل | در این پلتفرم |
|---|---|---|
| **کالا / کد کالا** | Stock item | قلم انبار با دسته: لوله، اتصالات، فلنج، شیر، ورق، پروفیل، پیچ و مهره، کابل، ابزار دقیق، مصرفی. هفت دستهٔ اول **قابل ردیابی ذوب** هستند. |
| **کاتالوگ MESC** | Material & Equipment Standards & Code | کدگذاری استاندارد کالا (قالب CSV در `docs/`). |
| **MRR / رسید** | Material Receiving Report | ورود کالا به انبار در برابر PO، با محل انبار؛ هر رسید یک **لات** می‌سازد. |
| **لات** | Lot | یک ورود مشخص از یک کالا، با شمارهٔ ذوب و MTC. |
| **شمارهٔ ذوب** | Heat number | شناسهٔ ذوب فولادساز؛ از رسید تا اسپول و جوش دنبال می‌شود. |
| **MTC** | Mill Test Certificate | گواهی کارخانهٔ فولاد (معمولاً EN 10204 نوع 3.1) با ترکیب شیمیایی و خواص مکانیکی همان ذوب. کالای قابل ردیابی بدون MTC پذیرفته‌شده حواله نمی‌شود. |
| **MIR** | Material Inspection Report | بازرسی رسید کالا: چشمی، ابعادی، شمارش؛ مقدار پذیرفته و ردشده. زیر ITP دریافت کالا (سه دسته: تحت فشار/سازه‌ای، الکتریکال و ابزار دقیق، عمومی). |

| **DCS / Historian** | سیستم کنترل توزیع‌شده / پایگاه دادهٔ تاریخچهٔ سیگنال‌ها (مثلاً PI)؛ شناسهٔ هر پارامتر (`70FT7001.PV`) در شناسنامهٔ نگهداری ثبت می‌شود. |

## ۱۴. کیفیت و بازرسی

| اصطلاح | کامل / معادل | در این پلتفرم |
|---|---|---|
| **ITP** | Inspection & Test Plan | برنامهٔ بازرسی هر نوع کار (مثلاً `ITP-ROT-70` برای تجهیز دوّار): ردیف‌ها با مرجع، معیار پذیرش، سند، و نقطهٔ بازرسی هر طرف. پیش‌نویس ← تأیید (نه توسط تهیه‌کننده) ← در حال اجرا (ثابت؛ تغییر فقط با رویژن جدید). |
| **نقاط بازرسی** | H / W / R / S | **H (Hold، توقف):** مرحله تا آزاد شدن ثبت نمی‌شود. **W (Witness، حضور):** طرف دعوت می‌شود؛ غیبتش پس از اطلاع‌رسانی کافی کار را آزاد می‌کند. **R (Review):** بررسی مدارک. **S (Surveillance):** نظارت. |
| **گره به مرحله** | — | ردیف ITP که به مرحله‌ای از زنجیره گره خورده؛ نقطهٔ H آن مرحله را قفل می‌کند. |
| **IR** | Inspection Request | درخواست بازرسی یک آیتم برای یک ردیف ITP، با زمان (آینده) و محل؛ طرف‌ها نتیجه را امضا می‌کنند: پذیرفته، پذیرفته با ملاحظات، رد، یا «حاضر نشد». |
| **اطلاع‌رسانی** | Notice hours | حداقل ساعت بین ثبت IR و زمان بازرسی (سیاست پروژه، مثلاً ۲۴). |
| **آزادسازی** | Release | وقتی همهٔ طرف‌های H/W نتیجهٔ پذیرفته داده‌اند (یا غیبت W موجه است). |
| **بازرسی دوباره** | Reinspection | IR جدید پس از رد؛ به IR ردشده ارجاع دارد. |
| **Punch** | Punch item | نقص ثبت‌شده در بازدید. **A** مانع MC، **B** مانع RFSU، **C** بدون توقف — به تحویل منتقل می‌شود. رفع (با یادداشت و تاریخ) ← تأیید و بستن (نفر دیگر) یا «رفع پذیرفته نشد». |
| **Walk-down** | — | بازدید میدانی پیش از MC برای ثبت پانچ‌ها. |
| **NCR** | Non-Conformance Report | عدم انطباق با نقشه/مشخصات/کد، با شدت **عمده/جزئی**. مسیر: باز ← پیشنهاد دیسپوزیشن ← تأیید ← اجرا ← بستن. |
| **دیسپوزیشن** | Disposition | استفاده به همین صورت (Use-as-is)، تعمیر، دوباره‌کاری طبق نقشه، مردود. دو مورد اول **ارفاق** (Concession) هستند و امضای مهندسی لازم دارند. |
| **تشدید NCR** | Escalation | NCR بازِ بیش از مدت تعیین‌شدهٔ پروژه به سطح بالاتر می‌رود. |
| **قبولی در بار اول** | First-pass yield | درصد IRهایی که در اولین بازرسی آزاد شده‌اند. |

## ۱۵. تکمیل و راه‌اندازی

| اصطلاح | کامل / معادل | در این پلتفرم |
|---|---|---|
| **MC** | Mechanical Completion | تکمیل مکانیکی یک ساب‌سیستم. امضا فقط وقتی «باز» خالی است: همهٔ تگ‌ها آماده، همهٔ خطوط در پکیج با تست پذیرفته، کابل‌ها و ابزارها تست‌شده، هیچ Punch A و NCR بازی نمانده. امضا (EPC) ← پذیرش (کارفرما). اگر پس از امضا چیزی باز شود: «دوباره باز شد». |
| **پیش‌راه‌اندازی** | Pre-commissioning | چک‌لیست‌های بین MC و RFC، بی‌سیال فرایندی: فلاشینگ خط، سولو ران موتور، … . هر چک‌لیست به ساب‌سیستم، تجهیز دوّار/ثابت/کوره، خط، کابل، ابزار یا لوپ **اعمال** می‌شود. |
| **فلاشینگ** | Flushing | شست‌وشوی خط تا آب تمیز در خروجی و صافی موقت بدون ذره. |
| **سولو ران** | Solo run | چرخاندن موتور بدون بار برای جهت چرخش و ارتعاش. |
| **تلاش** | Attempt | هر اجرای یک چک‌لیست (قبول/رد، با شاهد و یادداشت)؛ سابقهٔ همهٔ تلاش‌ها می‌ماند. |
| **RFC** | Ready for Commissioning | آماده برای راه‌اندازی: پس از پذیرش MC و پذیرش همهٔ چک‌لیست‌های پیش‌راه‌اندازی، بدون Punch A و NCR باز. |
| **راه‌اندازی** | Commissioning | روال‌های بین RFC و RFSU با سیال (مثلاً ران تست ۴ ساعتهٔ پمپ، کنترل سطح در حالت اتوماتیک). |
| **RFSU** | Ready for Start-Up | آماده برای راه‌اندازی با سیال فرایندی: پس از RFC و پذیرش همهٔ روال‌ها، بدون Punch A/B و NCR باز. |
| **تضمین عملکرد** | Performance guarantee | مقدار قراردادی (مثلاً ظرفیت ≥ ۳۰ m³/h)، با جهت (دست‌کم/حداکثر)، حداقل مدت و بند قرارداد. |
| **آزمون عملکرد** | Performance test | پس از RFSU همهٔ ساب‌سیستم‌های محدوده؛ نتیجهٔ هر تضمین «برآورده / برآورده نشده» را سامانه حکم می‌کند؛ امضا ← پذیرش. |

## ۱۶. HSE

| اصطلاح | کامل / معادل | در این پلتفرم |
|---|---|---|
| **PTW** | Permit to Work | مجوز کار: سرد، گرم، ورود به فضای بسته، ایزولاسیون برقی، حفاری، کار در ارتفاع، بالابری، رادیوگرافی. درخواست ← (تست گاز) ← صدور توسط نفر دیگر ← بستن. بازهٔ اعتبار زمان واقعی دارد و حداکثرش از مشخصات پروژه است. |
| **تست گاز** | Gas test | O₂ (مثلاً ۱۹٫۵ تا ۲۳٫۵٪)، LEL (حداکثر ۱۰٪)، H₂S و CO (ppm)؛ اعتبار آن چند دقیقه است (مثلاً ۱۲۰). |
| **LEL** | Lower Explosive Limit | حد پایین انفجار؛ درصدی از آن که دستگاه نشان می‌دهد. |
| **SIMOPS** | Simultaneous Operations | دو مجوز فعال هم‌زمان در یک محدوده که با هم تداخل دارند. |
| **LOTO** | Lock-Out Tag-Out | قفل و برچسب ایزولاسیون؛ شمارهٔ گواهی آن برای مجوز ایزولاسیون برقی لازم است. |
| **Standby / نگهبان** | Attendant | نفر بیرون فضای بسته؛ برای مجوز فضای بسته لازم است. |
| **JSA** | Job Safety Analysis | تحلیل ایمنی کار: هر گام با احتمال × شدت (۱ تا ۵) پیش و پس از کنترل‌ها؛ ریسک باقیمانده نباید از حد پروژه بیشتر باشد. |
| **کارت صلاحیت** | Competence card | آموزش HSE، کار در ارتفاع، تست گاز، ریگر، اپراتور جرثقیل، داربست‌بند، … با تاریخ انقضا؛ خدمهٔ مجوز با آن سنجیده می‌شوند. |
| **بازرسی داربست / جرثقیل** | — | با فاصلهٔ روز تعیین‌شدهٔ پروژه؛ تجهیزِ بازرسی‌نشده مجوز را نگه می‌دارد. |
| **ردهٔ حادثه (IOGP)** | Incident class | **FAT** فوتی، **LWC** روز کاری ازدست‌رفته، **RWC** کار محدود، **MTC** درمان پزشکی، **FAC** کمک‌های اولیه، **NM** شبه‌حادثه. رده از واقعیت‌ها حساب می‌شود، نه انتخاب. |
| **LTI / Recordable** | — | LTI = FAT + LWC؛ Recordable = FAT + LWC + RWC + MTC. |
| **LTIF / TRIR** | — | تعداد LTI یا Recordable به ازای **۱٬۰۰۰٬۰۰۰ نفرساعت** (IOGP) یا **۲۰۰٬۰۰۰** (OSHA). |
| **نفرساعت** | Man-hours | ساعت کار ثبت‌شدهٔ هر پیمانکار در روز؛ مخرج نرخ‌ها. |
| **مشاهده** | Observation | عمل ناایمن، شرایط ناایمن یا رفتار ایمن؛ با اقدام اصلاحی و مهلت. |

## ۱۷. کنترل پروژه

| اصطلاح | کامل / معادل | در این پلتفرم |
|---|---|---|
| **حساب کنترل** | Control account | واحد کنترل هزینه و پیشرفت (یک رشته یا بخشی از آن)، با BAC و خط مبنا. |
| **خط مبنا / منحنی S** | Baseline / S-curve | نقاط درصد تجمعی برنامه‌ریزی‌شده در زمان؛ PV روی هر تاریخ خطی بین نقاط خوانده می‌شود. |
| **BAC** | Budget at Completion | بودجهٔ کل حساب. |
| **PV / EV / AC** | Planned / Earned Value / Actual Cost | ارزش برنامه‌ای، ارزش کسب‌شده، هزینهٔ واقعی. **EV از خود رکوردهای پلتفرم** حساب می‌شود (جوش، کابل، ابزار، بتن، سازه، رنگ) با قاعدهٔ اعتبار پروژه (مثلاً ۷۰٪ در نصب، بقیه در تست)؛ درصد گزارش‌شدهٔ دستی جدا و با برچسب «گزارش‌شده». |
| **SV / CV** | Schedule / Cost Variance | SV = EV − PV، CV = EV − AC. |
| **SPI / CPI** | Schedule / Cost Performance Index | SPI = EV / PV، CPI = EV / AC (کمتر از ۱ = عقب / گران). |
| **EAC / VAC / TCPI** | — | EAC = BAC / CPI، VAC = BAC − EAC، TCPI = (BAC − EV) / (BAC − AC). |
| **اسنپ‌شات ماهانه** | Monthly snapshot | ثبت EV هر ماه برای منحنی واقعی. |
| **ریسک** | Risk | احتمال × اثر (۱ تا ۵) پیش و پس از پاسخ؛ شبکهٔ ۵×۵، مالک، مهلت. |

## ۱۸. تحویل به نگهداری (CMMS)

| اصطلاح | کامل / معادل | در این پلتفرم |
|---|---|---|
| **CMMS** | Computerized Maintenance Management System | سامانهٔ نگهداری بهره‌بردار (SAP PM، Maximo، FmWeb، …) که خروجی تحویل را می‌گیرد. |
| **شناسنامهٔ نگهداری** | Asset master | برای هر تگ: کلاس، بحرانیت، پلاک، شرایط طراحی، شناسه‌های DCS، و آمادگی تحویل. |
| **ISO 14224** | — | ردهٔ تجهیز (مثلاً **PU** پمپ، **VE** مخزن، **HE** مبدل حرارتی، **CO** کمپرسور…)؛ به انتخاب مهندس، از پیشوند تگ حدس زده نمی‌شود. |
| **FLOC** | Functional Location | مکان عملیاتی در CMMS از الگوی پروژه (مثلاً `{plant}-{unit}-{tag}` ← `DMW-70-P-7001`). |
| **بحرانیت** | Criticality | سطح (مثلاً A، B، C از مشخصات پروژه) با **مبنا** (گزارش ارزیابی). |
| **پلاک** | Nameplate | سازنده، مدل، سریال، سال ساخت. |
| **شرایط طراحی** | Design conditions | فشار و دمای طراحی؛ فقط با رویژن دیتاشیتِ همان تگ پذیرفته می‌شود. |
| **IOM** | Installation, Operation & Maintenance manual | دفترچهٔ فروشنده (کد دقیق «IOM» در VDRL)؛ بدون تأیید آن تحویل ممکن نیست. |
| **برنامهٔ PM** | Preventive Maintenance plan | تسک‌ها با راهبرد: **زمانی**، **وضعیت‌محور (CBM)**، **تا خرابی (RTF)** به‌عنوان تصمیم آگاهانه؛ بازه، تخصص، مدت، و **منبع** (دستورالعمل سازنده، RCM/FMEA، الزام قانونی، استاندارد شرکت). پیش‌نویس ← تأیید (نفر دیگر)؛ تغییر تسک تأییدشده = رویژن جدید. |
| **RCM / FMEA** | Reliability-Centred Maintenance / Failure Mode & Effects Analysis | مطالعه‌ای که بازه و راهبرد نگهداری را توجیه می‌کند. |
| **SPIR** | Spare Parts Interchangeability Record | فهرست قطعات یدکی هر تجهیز: دستهٔ **راه‌اندازی**، **بهره‌برداری (دوساله)**، **سرمایه‌ای/بیمه‌ای**؛ تعداد نصب‌شده، پیشنهاد فروشنده، تأیید مالک؛ و قطعات مشترک بین تجهیزها. |
| **کالیبراسیون دوره‌ای** | — | بازهٔ کالیبراسیون ابزارها پس از تحویل، با منبع. |
| **خروجی تحویل** | Export | CSV (سازگار با Excel) با ستون «ready = yes/no» و فهرست آنچه کم است؛ هر خروجی با هش SHA-256، زمان و نام کسی که آن را گرفته ثبت می‌شود. |
