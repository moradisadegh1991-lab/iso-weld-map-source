# لایهٔ ارائه‌دهندهٔ مدل (EPIC-6)

> سند مرجع: `docs/epc-llm/02-reference-architecture.md` §۲٫۱

هدف این لایه یک جمله است: **مهاجرت از API میزبان‌شده به خوشهٔ vLLM داخل سایت،
یک تغییر پیکربندی باشد نه بازنویسی.**

هیچ فایلی بالاتر از این پوشه نام Anthropic یا OpenAI را نمی‌داند. یک completion
می‌خواهد و `{ text, usage, stopReason, model }` می‌گیرد.

```
LLM_PROVIDER=anthropic          # پیش‌فرض
LLM_PROVIDER=openai-compatible  # + LLM_BASE_URL=http://vllm:8000/v1
LLM_PROVIDER=gemini             # + GEMINI_API_KEY=…
```

## Gemini (`gemini.mjs`)

درخواست مالک (۲۹ مهر ۱۴۰۵): اسکریپت‌های AI Studio او (`google-genai`، خروجی JSON) همین
فراخوان‌اند؛ اینجا از همان رابط مشترک می‌گذرند، پس خواندن ایزومتریک، پاس ترمیم و ورود مدارک
بی‌هیچ تغییری با Gemini کار می‌کنند — و خروجی همچنان از موتور قطعی و امضای انسان می‌گذرد.

- REST بی‌SDK: `models/{model}:streamGenerateContent?alt=sse`، کلید در هدر `x-goog-api-key`
  (نه در URL، تا در لاگ‌ها نماند).
- JSON با `generationConfig.responseMimeType: "application/json"`؛ پاسخ باز هم از
  `cleanJsonText`/`parseLoose` می‌گذرد.
- بخش‌های «فکر» مدل استدلالی (`thought: true`) جزو پاسخ نیستند و حذف می‌شوند؛ توکن‌های فکر
  از همان سقف `maxOutputTokens` خرج می‌شوند، پس در `output_tokens` شمرده می‌شوند.
- `MAX_TOKENS` → `max_tokens` (نقشهٔ بریده‌شده «ناقص» گزارش می‌شود)؛ رد ایمنی (`SAFETY`…)
  خطاست، نه نقشهٔ خالی.
- فهرست مدل‌ها همان فهرست فعلی گوگل (مهر ۱۴۰۵): Gemini 4 Argon، 3.8 Flash (پیش‌فرض)،
  3.5 Flash-Lite. خانوادهٔ 2.5 فقط برای کاربران قبلی است و 1.5 و 2.0 خاموش شده‌اند — مدل‌های
  اسکریپت‌های نمونه (`gemini-1.5-pro`، `gemini-2.0-flash`) دیگر پاسخ نمی‌دهند. `GEMINI_MODELS`
  فهرست را عوض می‌کند.
- رله روی Vercel (`deploy/gemini-relay`): Gemini به همهٔ کشورها سرویس نمی‌دهد. با
  `GEMINI_BASE_URL` (نشانی رله) و `GEMINI_RELAY_TOKEN` سرور فقط توکن رله را می‌فرستد و کلید
  Gemini روی Vercel می‌ماند.

## حساب مصرف (`accounting.mjs`)

هر فراخوان `/api/extract` — موفق یا ناموفق — در `llm_usage` (migration 082) ثبت می‌شود: پروژه،
کاربر، ارائه‌دهنده، مستقیم یا رله، مدل، پاس، توکن ورودی و خروجی، نتیجه و زمان. جدول فقط
افزودنی است (UPDATE و DELETE از app_rw پس گرفته شده؛ پیش‌فرض 001_core همه را می‌داد و آزمون
گرفتش). توکنی که ارائه‌دهنده نگفت NULL است، نه صفر. `LLM_PRICES` قیمت، `LLM_MONTHLY_TOKENS`
سهمیهٔ ماه؛ گزارش در صفحهٔ کاربران و دسترسی (`/api/llm-usage`).

آزمون: ۷ آزمون در `db/test/llm.mjs` با transport ساختگی؛ برداشتن فیلتر «فکر» یا نگاشت
`MAX_TOKENS` هر کدام آزمون را قرمز کرد. شکل نشانی و هدر روی خود سرور گوگل با کلید نادرست
سنجیده شد (پاسخ: «API key not valid» — یعنی نشانی و قالب پذیرفته شد). دقت استخراج Gemini روی
نقشه‌های golden هنوز سنجیده نشده — کلید لازم دارد.

## چرا این مهم است

سند ۰۰ بند ۵: دسترسی پایدار به OpenAI/Anthropic/Azure وجود ندارد، شبکهٔ OT جداست،
و نقشه و قرارداد مال ما نیست که بیرون بفرستیم. یعنی **خودمیزبانی اختیاری نیست.**

ولی تا وقتی خوشهٔ GPU بالا بیاید، کار باید جلو برود. پس امروز `anthropic` کار
می‌کند و فردا یک متغیر محیطی عوض می‌شود. این تنها راهی است که هر دو واقعیت را
همزمان می‌پذیرد.

## دو تفاوتی که adapter پنهان می‌کند

| | Anthropic | OpenAI-compatible (vLLM) |
|---|---|---|
| مجبور کردن به JSON | **prefill** نوبت assistant با `{` — مدل فیزیکاً نمی‌تواند preamble بنویسد | اغلب سرورها پیام assistant انتهایی را نادیده می‌گیرند؛ به‌جایش `response_format: json_object` که vLLM با guided decoding پیاده کرده |
| شمارش توکن | `input` فقط از `message_start`، `output` فقط از `message_delta` | فقط اگر `stream_options.include_usage` بخواهی |
| سقف توکن | `stop_reason: "max_tokens"` | `finish_reason: "length"` → به همان واژگان نگاشت می‌شود |

فراخوان هیچ‌کدام از این‌ها را نمی‌بیند. متن کامل JSON را می‌گیرد، هر ترفندی که
لازم بوده پشت صحنه انجام شده.

**هر دو stream می‌کنند** — نه برای نمایش تدریجی، بلکه چون یک generation طولانی
روی نقشهٔ شلوغ آن‌قدر پشت اتصال بی‌کار می‌ماند که پلتفرم قطعش می‌کند.

## `parse.mjs` — نردبان ترمیم

خروجی بریده‌شده، `null` برنمی‌گرداند اگر بشود نجاتش داد. ترمیم‌ها به ترتیب
«چقدر دور می‌ریزند» امتحان می‌شوند و اولین موردی که parse شود برنده است:

```
۱. همان‌طور که هست
۲. فقط براکت‌های باز بسته شوند
۳. جفت کلید/مقدار نیمه‌نوشته در انتها حذف شود
۴. اولین کلید یک شیء که بعد از کولونش بریده شده (کاما جلویش ندارد، پس قاعدهٔ ۳ نمی‌بیندش)
۵. همان، ولی با مقدار ناقص بعد از کولون
```

این ترتیب است که ترمیم‌های تهاجمی را بی‌خطر می‌کند: خروجی‌ای که فقط براکت کم
داشت، قبل از رسیدن به مرحله‌ای که مقدار سالم را دور می‌ریزد، برگشته است.

## استقرار vLLM (story 6.4)

```bash
docker run --gpus all -p 8000:8000 \
  -v ~/.cache/huggingface:/root/.cache/huggingface \
  vllm/vllm-openai:latest \
  --model Qwen/Qwen2.5-VL-32B-Instruct \
  --quantization awq \
  --max-model-len 32768 \
  --limit-mm-per-prompt image=10 \
  --guided-decoding-backend outlines
```

`--limit-mm-per-prompt image=10` حیاتی است: کاشی‌بندی تطبیقی روی اسکن ۳۰۰ DPI
شبکهٔ ۳×۳ می‌سازد، یعنی **۱۰ تصویر** (یک نمای کامل + ۹ کاشی) در یک درخواست.
پیش‌فرض vLLM یک تصویر است و درخواست رد می‌شود.

سایزینگ GPU در سند ۰۲ بند ۳.

## مقایسهٔ دو مسیر (story 6.5)

معیار پذیرش: **افت دقت کمتر از ۵٪ ⇒ سوییچ به داخلی.**

این هنوز قابل اجرا نیست و دلیلش فنی نیست: ارزیابی لایهٔ استخراج به **تصویر
نقشه** نیاز دارد، و `eval/cases/golden/` فعلاً فقط JSON استخراج‌شده دارد نه
فایل تصویر. همان گلوگاهی که رساندن دیتاست طلایی به ۵۰ نقشه را نگه داشته.

وقتی تصاویر اضافه شدند، رویه این است:

```bash
LLM_PROVIDER=anthropic         npm run eval:extraction   # مرجع
LLM_PROVIDER=openai-compatible npm run eval:extraction   # داخلی
```

و مقایسهٔ دقت فیلدی روی همان مجموعه. `input` هر مورد طلایی **همین حالا** حقیقت
مرجع استخراج است، پس ساختار داده آماده است — فقط تصویر کم دارد.

## تست

```bash
npm run db:test    # شامل ۲۵ تست این لایه
```

هر دو adapter در برابر یک transport ساختگی که SSE واقعی را بازپخش می‌کند تست
می‌شوند: بازسازی متن، شمارش توکن، نگاشت stop reason، ارسال تصویر، و رفتار در
برابر خطای upstream — بدون مدل، بدون کلید، بدون شبکه.
