# حلقهٔ انسان در جریان (EPIC-5)

> `lib/review/payload-diff.mjs` · `lib/db/repos/review.mjs` · `lib/disclaimer.mjs`

## ارزشمندترین دادهٔ این برنامه

هر اصلاحی که مهندس روی خروجی مدل انجام می‌دهد، **فیلدبه‌فیلد** ثبت می‌شود:

```json
{ "path": "nodes[1].E", "field": "E", "before": 118948, "after": 118984 }
```

این رکورد، مهم‌ترین دیتاستی است که این برنامه تولید می‌کند. دقت تجمعی به شما
می‌گوید مدل ۹۴٪ درست است؛ **این گزارش می‌گوید آن ۶٪ در کدام فیلد است** — و
تنها همین دومی قابل اقدام است.

اگر `nodes[].E` روی یک نقشه از هر سه اصلاح شود، prompt با ابعاد جاری مشکل
دارد. هیچ مقدار خیره شدن به دقت تجمعی این را نمی‌گفت.

```
GET /api/reports/edit-hotspots?projectId=…
```

اندیس‌ها حذف می‌شوند: `nodes[0].E` و `nodes[7].E` هر دو `nodes[].E` می‌شوند.
سؤال این است که **کدام فیلد** ضعیف است، نه کدام سطر این بار غلط بود.

## دقت لاگ مهم است

لاگی پر از اصلاح‌های ساختگی، بدتر از نبودن لاگ است. پس:

**`36` و `"36"` یک اصلاح نیستند.** رفت‌وبرگشت از تب JSON عدد را رشته می‌کند؛
ثبتش اصلاحات واقعی را زیر نویز دفن می‌کرد.

**آرایه‌ها با اندیس تطبیق می‌شوند.** برای `nodes` و `edges` درست است (به
ترتیب مسیرند) و برای `bom` هم در عمل با شمارهٔ قطعه می‌خواند. تطبیق بر اساس
محتوا، جابه‌جایی‌ای را که مهندس عمداً انجام داده پنهان می‌کرد.

## رجیستر **بازسازی** می‌شود، وصله نمی‌شود

وقتی اصلاحی اعمال می‌شود، موتور رجیستر را از payload اصلاح‌شده **از نو
می‌سازد**. موتور هنوز تنها چیزی است که تصمیم می‌گیرد جوش کجا بخورد — و یک
مختصات اصلاح‌شده می‌تواند مرز اسپول را دو مفصل آن‌طرف‌تر جابه‌جا کند.

شناسهٔ جوش از نسخهٔ قبلی منتقل می‌شود، پس اصلاح یک عدد در BOM، رکورد NDT
جوشی را که اصلاً دست نخورده یتیم نمی‌کند.

## صف بازبینی بر اساس «چقدر احتمال دارد غلط باشد»

```
GET /api/review-queue?projectId=…
```

مرتب‌سازی بر اساس خطای موتور، بعد تعداد WARN، بعد زمان. صفی که بر اساس زمان
ورود مرتب شود، از مهندس می‌خواهد خودش بدها را پیدا کند — کاری که موتور
اعتبارسنجی قبلاً انجام داده است.

## قفل، در خود پایگاه داده

تأیید که انجام شد، `locked_at` ست می‌شود — **با trigger، نه فقط در کد route**.
یک سرویس دوم، یک اسکریپت، یا یک route آینده نمی‌تواند فراموشش کند.

دو trigger:

| | |
|---|---|
| `extraction_run_lock` | تأیید ⇒ `locked_at = now()` |
| `extraction_run_locked_guard` | تغییر `payload` یا `validation_checks` روی اجرای قفل‌شده ⇒ exception |

و در لایهٔ API: ثبت اجرای جدید روی **همان رویژن سند** که رجیستر تأییدشده دارد،
با `REVISION_ALREADY_APPROVED` رد می‌شود. تنها مسیر مشروع، **رویژن جدید نقشه**
است — چون امضا در برابر همان بایت‌ها زده شده.

تست‌ها این را **از دو سمت** می‌سنجند: یک بار از طریق repository، و یک بار
مستقیم روی جدول — همان‌طور که یک اسکریپت آینده می‌رسد.

## UI

```
SessionBar   شناسه + پروژه (یک بار، مشترک بین همهٔ اجزا)
ReviewQueue  صف، مرتب بر اساس «چقدر احتمال دارد غلط باشد»
EditPanel    پیش‌نمایش تغییر، اعمال، و لاگ اصلاحات قبلی
```

**پیش‌نمایش، نکتهٔ اصلی است.** قبل از اینکه چیزی نوشته شود، مهندس دقیقاً
می‌بیند کدام فیلدها را دارد تغییر می‌دهد و هرکدام چه بود:

```
nodes[1].N     385918  →  386268
```

یک textarea پر از JSON این را خیلی راحت می‌کند که یک رقم را درست کنی و سه تای
دیگر را بی‌صدا خراب — و آن‌وقت لاگ هر چهار تا را **عمدی** ثبت می‌کند.

دو دکمهٔ متفاوت، و تفاوتشان مهم است:

| | |
|---|---|
| تب JSON → «اعمال محلی» | فقط نمای همین مرورگر را تازه می‌کند |
| تب بازبینی → «اعمال و ثبت اصلاح» | روی سرور ثبت می‌شود، با لاگ فیلدبه‌فیلد |

اجرای قفل‌شده اصلاً فرم اصلاح را نشان نمی‌دهد — به‌جایش امضاکننده، تاریخ و
اثر انگشت را نشان می‌دهد و می‌گوید تغییر بعدی رویژن جدید می‌خواهد.

## یک باگ که فقط اجرای واقعی نشانش داد

هر ۱۷۰ تست پاس بودند و `npm run build` سبز بود، ولی **هیچ route ای در
`npm run dev` کار نمی‌کرد**:

```
ERR_INVALID_ARG_TYPE: The "path" argument must be of type string…
  at @electric-sql/pglite/dist/chunk-…js
```

PGlite یک build وب‌اسمبلی دارد که فایل‌های خودش را نسبت به `import.meta.url`
پیدا می‌کند. وقتی webpack پکیج را bundle می‌کند، آن resolve یک شیء `URL`
می‌سازد جایی که Node مسیر رشته‌ای می‌خواهد.

تست‌ها نگرفتندش چون PGlite را در **Node خام** اجرا می‌کنند، بیرون از bundler.
رفع: `serverComponentsExternalPackages` در `next.config.mjs` برای
`@electric-sql/pglite` و `pg` — تا Next آن‌ها را در زمان اجرا require کند،
همان‌طور که تست‌ها می‌کنند.

این دقیقاً شکاف بین «تست سبز است» و «اپ کار می‌کند» بود، و تنها راه پیدا
کردنش بالا آوردن سرور و زدن به API واقعی بود.

## disclaimer روی خود مدرک، نه کنار دکمهٔ دانلود

خروجی این ابزار پیش‌نویس است. ولی روی اکسلی که ایمیل می‌شود، SVGای که چاپ و
در کارگاه نصب می‌شود، و CSVای که جای دیگری import می‌شود — در هر پرش، **دیگر
شبیه خروجی نرم‌افزار نیست، شبیه مدرک تأییدشده است.**

پس متن روی خود مدرک می‌رود:

| خروجی | کجا |
|---|---|
| اکسل | شیت `Disclaimer` + انتهای شیت `Weld Register` |
| CSV | انتهای فایل |
| SVG | دو سطر متن، درون خود فایل |
| صفحه | زیر جدول رجیستر |

`lib/disclaimer.mjs` تنها منبع متن است، تا عبارت بین اکسل و نقشه و صفحه واگرا
نشود. و خط امضا می‌گوید **چه کسی و در برابر کدام اثر انگشت** تأیید کرده —
«تأییدشده» بدون امضاکننده و بدون hash یک واژه است، نه یک رکورد.
