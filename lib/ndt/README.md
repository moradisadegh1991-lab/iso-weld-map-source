# موتور بازرسی غیرمخرب (EPIC-4)

> `lib/ndt/b31-3.mjs` · `requirement.mjs` · `sampling.mjs`

## مسئله‌ای که حل می‌کند

موتور تا امروز درصد NDT را هاردکد می‌کرد:

```js
ndt: w.loc === "Field" ? "RT 100%" : "RT 5% random"
```

دو ایراد داشت. اول اینکه **B31.3 هیچ تمایزی بین جوش کارگاه و سایت برای بازرسی
قائل نیست** — «جوش سایت ۱۰۰٪» یک **قاعدهٔ پروژه** است نه قاعدهٔ کد، و به‌صورت
قاعدهٔ کد ارائه می‌شد. دوم اینکه هیچ درصدی قابل ردیابی به منبعش نبود.

عددی روی رجیستر جوش که منبع قابل ردیابی نداشته باشد، عددی است که **نمی‌شود
جلوی بازرس از آن دفاع کرد.**

## دو مرجع، و ترتیبشان کل نکته است

```
۱. کف کد           B31.3 §341.4 برای دستهٔ سرویس
۲. Piping Class     فقط می‌تواند سخت‌گیرانه‌تر باشد
```

هر الزام تولیدشده `source` دارد: `code` یا `class`. Piping Class حاکم است،
ولی قاعده‌ای که **کمتر از کف کد** باشد **بی‌صدا اعمال نمی‌شود** — به‌عنوان
`CLASS_BELOW_CODE` گزارش می‌شود، چون کلاس قرارداد است و باید اعمال شود، ولی
انحراف از کد باید مصوب کارفرما باشد و کسی مالکش شود.

## کف کد

| دستهٔ سرویس | الزام | بند |
|---|---|---|
| Normal Fluid Service | RT ۵٪ **تصادفی** | §341.4.1 |
| Category D | VT (رادیوگرافی الزام کد نیست) | §341.4.2 |
| Severe Cyclic | RT ۱۰۰٪ | §341.4.3 |
| High Pressure (Ch. IX) | RT ۱۰۰٪ | §K341.4 |
| **Category M** | **تعیین‌نشده** | Ch. VIII §M341.4 |

Category M عمداً بدون عدد رها شده: M341.4 روی الزامات Normal بنا می‌شود، به
شکلی که به متریال و قواعد خود کارفرما بستگی دارد. **اختراع یک عدد اینجا بدتر
از اعتراف به نبودنش است.**

جوشی که butt محیطی نیست (fillet، socket) درصد رادیوگرافی نمی‌گیرد — بازرسی
سطحی می‌گیرد. شمردنش در جمعیت RT، نمونه را بی‌صدا رقیق می‌کند.

## «۵٪» یعنی «هر ۵٪»؟ نه.

§341.4.1(b) می‌گوید نمونه باید طوری انتخاب شود که **کار هر جوشکار در آن
باشد**.

نمونه‌ای که بدون این قید کشیده شود، می‌تواند پنج جوش از یک اکیپ بگیرد و هیچ
جوشی از کسی که نرخ تعمیرش دارد به مشکل تبدیل می‌شود — دقیقاً همان شکستی که
این بند برای جلوگیری از آن وجود دارد.

پس الگوریتم اول **از هر جوشکار یکی** برمی‌دارد، بعد تا رسیدن به درصد پر
می‌کند. وقتی تعداد جوشکارها از آنچه درصد اجازه می‌دهد بیشتر باشد، **پوشش
برنده است و نمونه بزرگ‌تر می‌شود** — این بند در حال کار کردن است، نه باگ.

## نمونه‌گیری بازتولیدپذیر — عمداً

انتخاب با **seed** انجام می‌شود و قطعی است. seed با خود انتخاب ذخیره می‌شود.

نمونهٔ «تصادفی» که هیچ‌کس نتواند بازتولیدش کند، **قابل ممیزی نیست**: وقتی
بازرس می‌پرسد چرا این جوش‌ها و نه بقیه، جواب باید یک **رویه** باشد نه شانه
بالا انداختن.

## Piping Class مرجع ضخامت هم هست

`piping_class_size` جدول سایز از روی برگهٔ مشخصات کلاس است: هر NPS، کدام
schedule، و ضخامت حاصل.

این **دادهٔ پروژه** است نه کپی B36.10M. و همین است که شکاف EPIC-3 را می‌بندد:
چک صلاحیت جوشکار تا امروز ضخامت را `NO_WALL_THICKNESS` گزارش می‌کرد، چون
برچسب schedule به‌تنهایی هرگز به کسی عددی نگفته است.

سایزی که کلاس فهرست نکرده، ضخامت ندارد و **درون‌یابی نمی‌شود**. ضخامتی که
کسی ننوشته، ضخامت نیست.

## پوشش

```js
coverage({ required, records })  →  { pct, welders, welderGaps }
```

`welderGaps` فهرستی است که موقع تحویل اهمیت پیدا می‌کند: جوشکارهایی که **هیچ
جوششان شات نشده**. «۹۲٪ کامل» دقیقاً همان یک جوشکار را پنهان می‌کند که
اسپول‌هایش در handover نگه داشته می‌شوند.

## API

```
GET  /api/piping-classes?projectId=…        هر کلاس به‌همراه کف کدی که رویش نشسته
POST /api/piping-classes                    (نقش engineer)
GET  /api/piping-classes/[id]/sizes
PUT  /api/piping-classes/[id]/sizes         (نقش engineer)
POST /api/runs/[id]/ndt-sample              اعمال الزام + کشیدن نمونه
GET  /api/ndt-selections/[id]/coverage
```

`POST /api/runs/[id]/ndt-sample` هر دو کار را با هم انجام می‌دهد چون به هم
تعلق دارند: نمونه تا وقتی هر جوش ندانَد زیر کدام الزام است معنا ندارد. هر
قاعدهٔ کلاس که زیر کف کد باشد در `deviations` برمی‌گردد.

## تست

`db/test/ndt.mjs` — ۲۴ تست. مهم‌ترین‌ها:

- قاعدهٔ کلاس زیر کف کد **اعمال می‌شود ولی به‌عنوان انحراف گزارش می‌شود**
- روش ضعیف‌تر حتی با ۱۰۰٪ هم زیر کد حساب می‌شود (PT ۱۰۰٪ جای RT ۵٪ نیست)
- همان seed همان جوش‌ها را می‌دهد؛ seed متفاوت، انتخاب متفاوت
- وقتی جوشکارها بیشتر از سهم درصدند، نمونه بزرگ می‌شود
- جوش بدون جوشکار **فهرست می‌شود**، نه اینکه بی‌صدا دورش بچرخیم
- و اینکه `NO_WALL_THICKNESS` بعد از تعریف کلاس دیگر گزارش نمی‌شود
