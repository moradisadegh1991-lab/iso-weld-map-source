# ISO Weld Map

آپلود نقشه ایزومتریک (JPG/PNG) ← استخراج داده ← مدل سه‌بعدی ← رجیستر سرجوش.

## معماری

مدل بینایی **فقط داده خام** را استخراج می‌کند (title block، BOM، مختصات گره‌ها).
شماره‌گذاری جوش، تقسیم اسپول و اعتبارسنجی توسط موتور قطعی در `lib/engine.js`
انجام می‌شود — نه توسط مدل زبانی. مراجع: ASME B16.9 (take-out زانوها)،
ASME B36.10M (قطر و ضخامت)، ASME B31.3 (NDT، preheat، PWHT).

## سه چک اعتبارسنجی خودکار

1. مجموع طول لوله مستقیم + pup در برابر مقدار PIPE در BOM
2. (لوله + pup + مجموع take-out ها) در برابر CL LENGTH در title block
3. بسته‌شدن مختصات دو سر خط (ΔE / ΔN / ΔEL)

اگر هرکدام نخواند، هشدار نمایش داده می‌شود و می‌توانید JSON استخراج‌شده را
در تب JSON اصلاح و دوباره اعمال کنید.

## اجرا

```bash
npm install

```

## دیپلوی روی Vercel

```bash
npx vercel --prod
```

سپس در Vercel › Settings › Environment Variables:

| متغیر | مقدار |
|---|---|
| `ANTHROPIC_API_KEY` | کلید API شما (اجباری برای آپلود نقشه) |
| `ANTHROPIC_MODEL`   | اختیاری، پیش‌فرض `claude-sonnet-5` (در UI هم قابل تغییر است) |

بدون کلید هم اپ کار می‌کند: دکمه «نمونه بدون کلید: SW 265022A» داده مرجع را بارگذاری می‌کند.
یا می‌توانید کلید را مستقیم در صفحه وارد کنید (فقط در همان درخواست استفاده می‌شود، ذخیره نمی‌گردد).

## قواعد تولید جوش

- Tie-in → ۱ جوش، همیشه Field
- زانو با pup piece → ۴ جوش؛ بدون pup → ۲ جوش
- سه‌راهی → ۳ (یا ۵ با pup) · تبدیل → ۲ · فلنج WN → ۱ · شیر BW → ۲ · شیر فلنجی → ۰
- ران مستقیم بلندتر از `maxPipeLength` (پیش‌فرض ۱۲ m) → girth weld میانی
- ران مستقیم بلندتر از `spoolMaxLen` (پیش‌فرض ۶ m) → دو سرش Field Closure می‌شود
- مرز اسپول‌ها دقیقاً روی جوش‌های Field می‌نشیند

## سلب مسئولیت

خروجی این ابزار **پیش‌نویس** است. قبل از ساخت باید توسط مهندس پایپینگ در برابر
آخرین رویژن نقشه، Piping Class پروژه و Fabrication Philosophy پیمانکار بازبینی و تأیید شود.
درصد NDT پیش‌فرض بر مبنای B31.3 §341.4.1 برای Normal Fluid Service است و Piping Class حاکم است.

## رفع خطاهای رایج

### `Unexpected token 'A', "An error o"... is not valid JSON`
تابع در سطح پلتفرم شکسته و Vercel یک صفحه متنی برگردانده. کلاینت حالا پاسخ را اول
به‌صورت متن می‌خواند، پس متن واقعی خطا (همراه کد) نمایش داده می‌شود.

### `FUNCTION_INVOCATION_TIMEOUT`
تولید کل JSON در یک درخواست از سقف زمانی تابع رد می‌شد. حل‌شده با:

- **دو پاس موازی** — `pass: "meta"` (title block + BOM) و `pass: "nodes"` (هندسه)
  به‌صورت هم‌زمان از کلاینت فراخوانی می‌شوند. زمان کل = بیشینه‌ی دو تا، نه جمعشان.
- **max_tokens کوچک‌تر** — ۳۰۰۰ برای meta و ۲۰۰۰ برای nodes، به‌جای ۸۰۰۰.
- **streaming** از Anthropic تا اتصال در طول تولید فعال بماند.
- **یک بار retry خودکار** روی ۵۰۲/۵۰۴.
- **انتخاب مدل در UI** — دکمه «مدل سریع» مقدار `claude-haiku-4-5-20251001` را می‌گذارد.

سقف زمانی تابع: Hobby ۶۰ ثانیه، Pro تا ۳۰۰ ثانیه (`maxDuration` در route روی ۳۰۰ است
و روی Hobby خودکار به ۶۰ محدود می‌شود). اگر روی Hobby هستید و باز تایم‌اوت گرفتید،
اول «مدل سریع» را امتحان کنید.

### حجم بدنه درخواست
سقف توابع Vercel حدود ۴.۵ مگابایت است. تصویر در **مرورگر** به یک نمای کامل + چهار کاشی
هم‌پوشان تقسیم و به ۱۵۰۰ px فشرده می‌شود؛ اگر باز بزرگ بود کیفیت پله‌پله تا زیر ۳.۴ MB
پایین می‌آید. تقسیم به کاشی، دقت خواندن BOM و ابعاد ریز را هم بالا می‌برد.

### `پاسخ مدل در پاس nodes JSON نبود`
خروجی مدل هیچ آکولاد بازی نداشت — یعنی به‌جای JSON، متن نوشته بود یا وسط تولید بریده شده بود.
حل‌شده با:

- **Assistant prefill** — نوبت assistant با `{` از پیش پر می‌شود، پس مدل فیزیکاً نمی‌تواند
  preamble بنویسد و فقط می‌تواند JSON را ادامه دهد.
- **`parseLoose`** — اگر خروجی وسط ساختار بریده باشد، براکت‌های باز شمرده و بسته می‌شوند
  و دوباره parse می‌شود؛ داده ناقص بهتر از شکست کامل است.
- **`max_tokens` هر دو پاس به ۴۰۰۰** و گزارش `stop_reason` در پیام خطا.
- **قاعده صریح در پرامپت** — «هرگز رد نکن و توضیح نده؛ اگر مختصات میانی درنیامد،
  فقط tie-in ها را بده و بقیه را در `unreadable` بنویس».
- **`Promise.allSettled`** — اگر یک پاس بشکند، نیمه دیگر بارگذاری می‌شود، تب JSON باز
  می‌شود و می‌توانید نیمه گمشده را دستی وارد کنید. دیگر بن‌بست نداریم.
- خروجی خام مدل در پیام خطا نمایش داده می‌شود.
