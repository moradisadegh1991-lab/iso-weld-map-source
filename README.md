# ISO Weld Map

آپلود نقشه ایزومتریک (JPG/PNG) ← استخراج داده ← مدل سه‌بعدی ← رجیستر سرجوش.

## معماری

مدل بینایی **فقط داده خام** را استخراج می‌کند (title block، BOM، مختصات گره‌ها).
شماره‌گذاری جوش، تقسیم اسپول و اعتبارسنجی توسط موتور قطعی در `lib/engine.js`
انجام می‌شود — نه توسط مدل زبانی. مراجع: ASME B16.9 (take-out زانوها)،
ASME B36.10M (قطر و ضخامت)، ASME B31.3 (NDT، preheat، PWHT).

## سه چک اعتبارسنجی خودکار

1. مجموع طول لوله مستقیم + pup در برابر مقدار PIPE در BOM
2. (لوله + pup + مجموع take-out ها) در برابر CL LENGTH در title block
3. بسته‌شدن مختصات دو سر خط (ΔE / ΔN / ΔEL)

اگر هرکدام نخواند، هشدار نمایش داده می‌شود و می‌توانید JSON استخراج‌شده را
در تب JSON اصلاح و دوباره اعمال کنید.

## دیپلوی روی Vercel

```bash
npx vercel --prod
```

سپس در Vercel › Settings › Environment Variables:

| متغیر | مقدار |
|---|---|
| `ANTHROPIC_API_KEY` | کلید API شما (اجباری برای آپلود نقشه) |
| `ANTHROPIC_MODEL`   | اختیاری، پیش‌فرض `claude-sonnet-5` (در UI هم قابل تغییر است) |

بدون کلید هم اپ کار می‌کند: دکمه «نمونه بدون کلید: SW 265022A» داده مرجع را بارگذاری می‌کند.
یا می‌توانید کلید را مستقیم در صفحه وارد کنید (فقط در همان درخواست استفاده می‌شود، ذخیره نمی‌گردد).

## قواعد تولید جوش

- Tie-in → ۱ جوش، همیشه Field
- زانو با pup piece → ۴ جوش؛ بدون pup → ۲ جوش
- سه‌راهی → ۳ (یا ۵ با pup) · تبدیل → ۲ · فلنج WN → ۱ · شیر BW → ۲ · شیر فلنجی → ۰
- ران مستقیم بلندتر از `maxPipeLength` (پیش‌فرض ۱۲ m) → girth weld میانی
- ران مستقیم بلندتر از `spoolMaxLen` (پیش‌فرض ۶ m) → دو سرش Field Closure می‌شود
- مرز اسپول‌ها دقیقاً روی جوش‌های Field می‌نشیند

## سلب مسئولیت

خروجی این ابزار **پیش‌نویس** است. قبل از ساخت باید توسط مهندس پایپینگ در برابر
آخرین رویژن نقشه، Piping Class پروژه و Fabrication Philosophy پیمانکار بازبینی و تأیید شود.
درصد NDT پیش‌فرض بر مبنای B31.3 §341.4.1 برای Normal Fluid Service است و Piping Class حاکم است.

## رفع خطاهای رایج

### `Unexpected token 'A', "An error o"... is not valid JSON`
تابع در سطح پلتفرم شکسته و Vercel یک صفحه متنی برگردانده. کلاینت حالا پاسخ را اول
به‌صورت متن می‌خواند، پس متن واقعی خطا (همراه کد) نمایش داده می‌شود.

### `FUNCTION_INVOCATION_TIMEOUT`
تولید کل JSON در یک درخواست از سقف زمانی تابع رد می‌شد. حل‌شده با:

- **دو پاس موازی** — `pass: "meta"` (title block + BOM) و `pass: "nodes"` (هندسه)
  به‌صورت هم‌زمان از کلاینت فراخوانی می‌شوند. زمان کل = بیشینه‌ی دو تا، نه جمعشان.
- **max_tokens کوچک‌تر** — ۳۰۰۰ برای meta و ۲۰۰۰ برای nodes، به‌جای ۸۰۰۰.
- **streaming** از Anthropic تا اتصال در طول تولید فعال بماند.
- **یک بار retry خودکار** روی ۵۰۲/۵۰۴.
- **انتخاب مدل در UI** — دکمه «مدل سریع» مقدار `claude-haiku-4-5-20251001` را می‌گذارد.

سقف زمانی تابع: Hobby ۶۰ ثانیه، Pro تا ۳۰۰ ثانیه (`maxDuration` در route روی ۳۰۰ است
و روی Hobby خودکار به ۶۰ محدود می‌شود). اگر روی Hobby هستید و باز تایم‌اوت گرفتید،
اول «مدل سریع» را امتحان کنید.

### حجم بدنه درخواست
سقف توابع Vercel حدود ۴.۵ مگابایت است. تصویر در **مرورگر** به یک نمای کامل + چهار کاشی
هم‌پوشان تقسیم و به ۱۵۰۰ px فشرده می‌شود؛ اگر باز بزرگ بود کیفیت پله‌پله تا زیر ۳.۴ MB
پایین می‌آید. تقسیم به کاشی، دقت خواندن BOM و ابعاد ریز را هم بالا می‌برد.

### `پاسخ مدل در پاس nodes JSON نبود`
خروجی مدل هیچ آکولاد بازی نداشت — یعنی به‌جای JSON، متن نوشته بود یا وسط تولید بریده شده بود.
حل‌شده با:

- **Assistant prefill** — نوبت assistant با `{` از پیش پر می‌شود، پس مدل فیزیکاً نمی‌تواند
  preamble بنویسد و فقط می‌تواند JSON را ادامه دهد.
- **`parseLoose`** — اگر خروجی وسط ساختار بریده باشد، براکت‌های باز شمرده و بسته می‌شوند
  و دوباره parse می‌شود؛ داده ناقص بهتر از شکست کامل است.
- **`max_tokens` هر دو پاس به ۴۰۰۰** و گزارش `stop_reason` در پیام خطا.
- **قاعده صریح در پرامپت** — «هرگز رد نکن و توضیح نده؛ اگر مختصات میانی درنیامد،
  فقط tie-in ها را بده و بقیه را در `unreadable` بنویس».
- **`Promise.allSettled`** — اگر یک پاس بشکند، نیمه دیگر بارگذاری می‌شود، تب JSON باز
  می‌شود و می‌توانید نیمه گمشده را دستی وارد کنید. دیگر بن‌بست نداریم.
- خروجی خام مدل در پیام خطا نمایش داده می‌شود.

## نسخه ۲ موتور — پشتیبانی از خطوط واقعی

نسخه اول فرض می‌کرد مسیر یک **زنجیره خطی تک‌قطر** است. ایزوی SW 265017A
(سه‌راهی تبدیلی 32x18، سه tie-in، دو قطر، دو برگ) این فرض را شکست. تغییرات:

| از | به |
|---|---|
| `nodes` به‌صورت زنجیره | **گراف** با آرایه `edges` — سه‌راهی سه یال دارد |
| یک `nps` سراسری | `nps` روی هر یال؛ رندر و MTO چندقطری |
| take-out فقط زانو | جدول B16.9 برای سه‌راهی (C) و تبدیل هم اضافه شد |
| سه‌راهی = ۳ یا ۵ جوش | **۶ جوش** با pup (سه سر × دو جوش) — pup روی هر سرِ اتصال |
| مرز اسپول با قاعده «ران بلند» | **حد طول حمل** — راه‌رفتن حریصانه روی مسیر و برش closure هر جا اسپول از سقف رد شود |
| اسپول با پیمایش خطی | **Union-Find** روی گراف عناصر؛ اسپول = مؤلفه متصل از میان جوش‌های کارگاهی |
| اعتبارسنجی یک‌قطره | مقایسه به تفکیک قطر با ردیف متناظر MTO |
| بی‌خبر از چندبرگی بودن | هشدار: اگر MTO مجموع کل خط باشد، مقایسه با هندسه یک برگ بی‌معناست |

مسیریابی: بلندترین مسیر بین دو انتها به‌عنوان ران اصلی شماره‌گذاری می‌شود، سپس
شاخه‌ها — همان ترتیبی که یک weld map واقعی دارد.

## نسخه ۳ — دقت، نماهای انتخابی، خروجی اکسل، نقشه دوبعدی

### دقت استخراج
- **جدول کامل B16.9 داخل پرامپت** — قبلاً فقط مقادیر DN900 هاردکد بود، پس فقط برای
  خطوط ۳۶ اینچ self-check داشت. حالا جدول ELL90 / ELL45 / TEE برای همه سایزها از
  `lib/standards.js` تولید و تزریق می‌شود، و مدل موظف است هر بُعد را با آن بخواند.
- **`temperature: 0`** روی هر سه پاس.
- **کاشی‌بندی تطبیقی** — منبع با ضلع بلند ≥ ۳۲۰۰ px شبکه **۳×۳** می‌گیرد (۱۰ تصویر)،
  وگرنه ۲×۲ (۵ تصویر). هم‌پوشانی ۱۴٪ تا هیچ ردیف BOM روی مرز بریده نشود.
- **پاس اصلاح خودکار (`pass: "repair"`)** — بعد از ادغام، موتور اعتبارسنجی اجرا می‌شود؛
  اگر چکی WARN بدهد، JSON به‌همراه فهرست چک‌های شکست‌خورده و همان کاشی‌ها دوباره به
  مدل داده می‌شود تا خودش عدد غلط را پیدا کند. اگر نتیجه بدتر شد، نسخه اول نگه داشته
  می‌شود — پاس اصلاح هرگز کیفیت را پایین نمی‌آورد.

### نماهای سه‌بعدی انتخابی
`توپر` · `شفاف (X-ray)` · `مش` · `تک‌خط` — به‌علاوه انتخاب رنگ‌بندی:
`اسپول` / `قطر` / `خنثی`. نمای شفاف برای دیدن جوش‌های داخل اسپول و تک‌خط برای
مرور توپولوژی خطوط بلند.

### نقشه دوبعدی جوش
`components/WeldMap2D.jsx` — تصویربرداری SVG با تصویر ایزومتریک واقعی
(سه محور ۱۲۰ درجه از هم: شرق ۳۰°، شمال ۱۵۰°، ارتفاع قائم). ضخامت خط با قطر لوله
مقیاس می‌گیرد، تگ‌های جوش با leader line و جانمایی ضدتداخل نوشته می‌شوند، و
tie-in ها با مرجع و EL کالت می‌خورند. زوم و پن دارد و **دانلود SVG** — برداری،
پس در هر ابعادی بدون افت چاپ می‌شود.

### خروجی اکسل
`lib/excel.js` با SheetJS، پنج شیت:
`Line Data` · `Weld Register` (با freeze pane و autofilter، ستون‌های WPS/Welder/NDT
Report/Status خالی برای QC) · `Spool List` · `MTO` (نقشه در برابر محاسبه‌شده) ·
`Validation`. خروجی CSV هم برای سازگاری باقی مانده است.

## نسخه ۳.۱ — رفع باگ پاس اصلاح و انتخاب مدل

### باگ بحرانی: پاس اصلاح می‌توانست نقشه را نابود کند
گارد قبلی فقط تعداد WARN را مقایسه می‌کرد. وقتی پاس اصلاح گره‌ها را حذف می‌کرد،
`buildModel` یک `error` برمی‌گرداند و آرایه `checks` **خالی** می‌شد — یعنی صفر WARN،
یعنی گارد آن را «بهتر» می‌دید و نتیجه خراب را می‌پذیرفت.

گارد جدید سه شرط دارد و هر سه باید برقرار باشند:

```
score(m) = (m.error ? 1000 : 0) + تعداد WARN
پذیرش فقط اگر:  score(بعد) < score(قبل)
             و  تعداد گره‌ها کم نشده باشد
             و  حداقل دو گره باقی مانده باشد
```

در پرامپت پاس اصلاح هم قواعد سخت اضافه شد: حذف گره یا یال ممنوع مگر آنکه یک چک
شکست‌خورده صریحاً آن را جعلی بنامد؛ «بدون تغییر» یک پاسخ معتبر است.

### لایه پاک‌سازی قطعی (`sanitize`)
مستقل از مدل، قبل و بعد از پاس اصلاح اجرا می‌شود:
- `nps` باید یکی از قطرهای ستون DIAM در MTO باشد؛ وگرنه با بزرگ‌ترین قطر MTO جایگزین می‌شود
  (این دقیقاً باگ `nps = 3` به‌جای `36` را می‌گیرد)
- گره بدون مختصات عددی یا با مختصات تکراری حذف می‌شود
- یال با مرجع گره ناموجود حذف می‌شود

### انتخاب مدل
سه گزینه در UI: **Opus 5** (دقیق‌ترین)، **Sonnet 5** (پیش‌فرض)، **Haiku 4.5** (سریع).
پاس اصلاح مدل مستقل دارد و پیش‌فرضش **Opus 5** است — خروجی این پاس کوچک است، پس
ارتقا به قوی‌ترین مدل نه گران است نه ریسک تایم‌اوت دارد. یعنی: استخراج سریع، اصلاح دقیق.

### هشدار رزولوشن
اگر ضلع بلند تصویر زیر ۲۲۰۰ px باشد، هشدار صریح داده می‌شود که BOM و ابعاد ریز
قابل اتکا نیستند و حداقل ۲۵۰۰ px (ترجیحاً اسکن ۳۰۰ DPI از PDF) لازم است.

### حسابداری توکن
`input_tokens` فقط از `message_start` و `output_tokens` فقط از `message_delta` خوانده
می‌شود؛ قبلاً ادغام کورکورانه اعداد را جابه‌جا نشان می‌داد.
